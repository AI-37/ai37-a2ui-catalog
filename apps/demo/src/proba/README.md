# `/proba` — ревизия и сборка примитивов каталога

Песочница в demo, не код пакета. Здесь примитивы каталога сводятся к минимальному
набору и проверяются на настоящем экране, прежде чем что-то менять в
`packages/catalog-react`.

**Примитивы больше не живут здесь.** Они переехали в
`packages/catalog-react/src/primitives` (change `constructions-editor-next`), и
песочница импортирует их из пакета:

```ts
import {Button, Card, Field, Form, KitStyles, Lookup} from '@ai37/a2ui-catalog-react/primitives';
```

Копии в `/proba` удалены — иначе правка примитива расходилась бы с тем, что видит
рендерер. Класс-корень набора теперь `a2ui-kit`, а не `a2ui-proba`: под ним
объявлены все правила, и его же несёт корень `ConstructionsEditorNext`.

`/proba/system` — **реестр**, а не витрина: примитив, добавленный или изменённый
по ходу работы над рендерером, обязан появиться там в том же change. Примитив,
живущий в `primitives/`, но не показанный на `/proba/system`, считается
незавершённым.

## Метод

Порядок обязателен — он и есть суть, а не оформление.

1. **Ревизия из кода, с числами.** Не «кнопок много», а 9 семейств / 31 образец /
   6 покопийных дублей — посчитано по `renderers/*-styles.ts`. Числа спорить не
   дают.
2. **Свести к минимуму, а не к красивому.** Если различие меняет не размер, а
   начертание или режим набора — это модификатор, а не новая ступень. Так девять
   кеглей стали тремя (26/14/12), а восемь семейств кнопок — одной с осями
   `variant × size × tone`.
3. **Проверка — сборка настоящего экрана.** Не витрина примитивов, а тот самый
   `ConstructionsEditor`: `/proba/assembly`. Хватило набора или нет — видно сразу.
4. **Чего нет на экране — не добавлять.** ГСОП остаётся «—»: его считает агент.
   Слои есть только у стены — остальные конструкции раскрываются пустыми, потому
   что их состава на экране не видели.
5. **Расхождения ищутся глазами.** Пропавший при сворачивании заголовок «Условия»
   нашёлся не в CSS, а когда два скриншота положили рядом.
6. **Занести в пакет, а не оставить в песочнице.** Набор, доказавший себя на
   экране, переезжает в `packages/catalog-react/src/primitives`, и первый
   настоящий потребитель — рендерер рядом со старым, а не вместо него:
   `ConstructionsEditorNext` на той же схеме props, чтобы «было / стало» можно
   было положить рядом в одном треде демо.
7. **Build-vs-buy до кода.** Прежде чем писать попап с клавиатурой — посмотреть
   готовое. `/proba/lookup` сравнивает наш `LookupCombobox` с Base UI
   Autocomplete на одном справочнике.

## Страницы

| роут | что показывает |
|---|---|
| `/proba/system` | готовый набор: типографика, кнопка, карточка, форма, раскрывашки, меню |
| `/proba/assembly` | экран конструкций, собранный из этого набора |
| `/proba/lift-assembly` | экран лифтов: две методики, у каждой свой состав формы |
| `/proba/keo-assembly` | экран КЕО: условия и два помещения секциями, аккордеон внутри аккордеона |
| `/proba/report-assembly` | отчёты: теплотех в двух режимах и лифты, один под другим |
| `/proba/lookup` | поиск по справочнику: наш против Base UI |
| `/proba/revision` | что в каталоге есть сегодня, с числами |

## Что своё, а что из Base UI

| берём из библиотеки | остаётся своим |
|---|---|
| `Autocomplete` — поиск по справочнику | оформление всех примитивов (классы `a2ui-*`) |
| `Select` — назначение помещений, условия эксплуатации | `Chip`, статус конструкции |
| `NumberField` — tв, tот, zот, tн (без кнопок-ступеней) | `useLookupSuggest` — debounce, abort, minChars |
| `Field` — связка подписи и контрола | подстановка климата (`readOptionClimate`) |
| `Collapsible` — блок «Условия» | шкала, слой токенов, уровни карточки |
| `Accordion` — список конструкций (одна за раз) | |
| `Menu` — «Скачать» и действия карточки конструкции | |

Правило одно: **поведение библиотечное, вид наш.** Части Base UI рендерят свой
элемент, поэтому класс им отдаётся снаружи — `buttonClassName()` и
`cardClassName()` существуют ровно для этого.

## Из чего собран `/proba/lift-assembly`

Второй экран на том же наборе. Он сложнее конструкций тремя вещами: две
методики перестраивают состав формы без раунд-трипа, ряды подсказок зависят от
поля здания, а секции носят пометки состояния.

**Экран больше не живёт здесь.** Он переехал в пакет вместе с рендерером
`LiftEditorNext` (change `lift-editor-next`), и страница импортирует его
частями оттуда — второй экземпляр разошёлся бы с рендерером первой же правкой:

```ts
import {LiftNextScreen} from '../../../../packages/catalog-react/src/renderers/lift-next-screen';
```

```
LiftAssembly × 2           ветка 52941 и ветка 34758 на одной странице
  LiftNextScreen           экран из пакета; наружу вместо dispatchAction — консоль
    Card                   карточка-рама сообщения
      Card flat            шапка утопленной полосой: титул тянется, остальное вправо
        CardHeader         титул + контекст + Menu trigger="link" (методика)
      Accordion.Root       секции, раскрыта одна за раз (multiple=false, значение управляемое)
        SectionItem        Accordion.Item: Trigger (шеврон, титул, сводка), Chip, «Удалить лифт»
          LiftNextFields   Form → LiftNextField → NumberField / Select / Combo + SourceNote
            SummaryCollapsible  «Параметры по умолчанию» со сводкой принятых значений
      Button link accent   «Добавить лифт» — вне Accordion.Root
      Button filled lg     «Далее» ↔ «Рассчитать»
```

Логику экран не пишет заново — берёт готовые модули пакета:
`apply-dependent-rules`, `resolve-lift-field-options`, `split-advanced-fields`,
`build-lift-section-summary`, `seed-lift-values`, `create-lift-editor-drafts`,
`omit-touched-lift-sources`, `shift-sections-after-remove`. Песочница проверяет
вид и клавиатуру, а не второй раз считает то же самое.

Наполнение — валидные фикстуры каталога (`fixtures/valid/lift-editor-per-lift.json`
и `lift-editor-group.json`), разобранные схемой: JSON и типы разъезжаются
молча, а `parse` роняет страницу на первом расхождении.

Примитивы, которых для этого экрана не хватало, переехали в пакет вместе с ним
и показаны на `/proba/system`:

- **`Combo`** — свободный ввод с рядом-подсказкой (Q, Vn, ширина двери).
  `Select` запрещает своё значение, `Lookup` ходит в справочник по
  `referenceId`, а ряд ГОСТ приходит в наполнении и живёт на клиенте. Под низом
  тот же Base UI `Autocomplete`, `mode="none"` — фильтрация прятала бы остаток
  ряда после первой набранной цифры. Пустой ряд — обычный `Input`.
- **`Chip tone="warning"`** — «заполните» / «просмотреть». Отдельного
  `SectionBadge` не завелось: формой это пилюля, новым был только тон
  предупреждения (`success` и `danger` уже были), а слова пометок знает экран.
- **`Menu trigger="link"`** — третья форма триггера меню: подпись с кареткой,
  без рамки. Под ним не действие, а выбранное значение шапки — рамка обещала бы
  кнопку. Пункты, попап и клавиатура прежние, это ось триггера, а не отдельный
  компонент.
- **`SectionItem`** — секция-раскрывашка со сводкой, пометкой и действием в
  шапке: элемент `Accordion` с классом карточки.
- **`SummaryCollapsible`** — свёрнутый блок со сводкой принятого («Параметры по
  умолчанию»): не слепой экспандер, что внутри — видно без клика.
- **`SourceNote`** — подпись под контролом: откуда взялось значение
  (`note` агента или слово из словаря провенанса каталога).

## Из чего собран `/proba/keo-assembly`

Четвёртый экран и самый большой опросник каталога: 23 поля в пяти секциях,
два помещения, четыре вида провенанса в наполнении, три правила
предупреждающей валидации и ветка из пяти полей, которая появляется по
значению поля-триггера.

Сложность у него своя, не как у лифтов: там состав формы переключала методика,
здесь — **вложенность**. Помещение перестало быть вкладкой и стало секцией со
своими секциями внутри, то есть аккордеон внутри аккордеона; из-за этого
раскрытие живёт одним множеством ключей на весь экран, а не состоянием каждого
списка.

Экран пока живёт здесь, а не в пакете: рендерер `KeoEditorNext` — следующий
change, и переносить его до осмотра значило бы поверить набору на слово.

```
KeoAssembly                  экран страницы; наружу вместо dispatchAction — консоль
  Card                       карточка-рама сообщения
    Card flat + CardHeader   титул «Параметры расчёта КЕО» + мета; слот action пуст
    Accordion.Root multiple  внешний список: условия и помещения
      SectionItem «Условия расчёта»   KeoAssemblyConditions: Form → Field →
                                    Lookup (город) / Static boxed (выведенное)
      KeoAssemblyRoom × 2             SectionItem: сводка (назначение и габариты),
        Chip                          пилюля «заполните» / «просмотреть»,
        Menu icon-only                «Удалить помещение», tone: 'danger'
        Accordion.Root multiple       внутренний список секций помещения
          KeoAssemblySection × 4      «Назначение» · «Геометрия» · «Светопроём» · «Затенение»
            KeoAssemblyFields         Form → Field → Select / NumberField
              KeoAssemblyFieldNotes   источник · пояснение варианта · «! проверить»
              KeoAssemblyComputedNote плоскость и точка расчёта — Field + Static
        SummaryCollapsible            «Коэффициенты приняты по умолчанию» со сводкой
    KeoAssemblyAddRoom       Button outline dashed «+ Добавить помещение»
    KeoAssemblyFooter        Button filled lg «Далее» ↔ «Рассчитать» + счётчик источников
```

Логику экран не пишет заново — берёт готовые модули пакета, общие с нынешним
`KeoEditor`: `evaluate-keo-rules`, `resolve-keo-computed-note`,
`is-revealed-field`, `seed-calc-values`, `count-calc-sources`,
`format-calc-source-counter`, `calc-field-range-warning`,
`build-calc-section-summary`, `create-calc-screens`, `calc-touched-key`. Два
экрана обязаны вести себя одинаково, а не считать одно и то же дважды.

Наполнение — валидная фикстура каталога (`fixtures/valid/keo-editor.json`),
разобранная `keoEditorPropsSchema`. Второе помещение — копия первого без
имени: второй набор значений пришлось бы выдумать, а сводку свёрнутого
помещения и счётчик **всего** документа на одном помещении не проверить.

Условия — поля формы, а не строки текста. Вопрос «как здесь изменить город»
ответа не имел, пока значение стояло голым `Static`: на макете это поля, и у
региона стоит справочник. Строка условий получила `type` / `options` /
`referenceId` / `source`; без `type` она остаётся значением — так приходит
выведенное (норматив e_н, методика), его пересчитывает агент. Правленое
условие уходит в submit тем же ключом: «изменить только для расчёта» и значит,
что правка меняет расчёт, а не данные проекта.

Новых примитивов экран не завёл — хватило двух осей существующих:

- **`Static boxed`** — значение в залитой коробке контрола
  (`a2ui-control--ready`). Не новая идея: ровно так с первого макета живёт
  `a2ui-ce-control--project` в `ConstructionsEditor` — в набор заливку просто
  не перенесли. Понадобился свой токен `--a2ui-control-surface-ready`: на
  равном с фоном сером коробка внутри утопленной секции исчезала совсем.
- **`SourceNote` знает шесть видов провенанса.** Было четыре
  (`project`, `question`, `suggested`, `default`); расчётные редакторы приносят
  `calculated` (значение посчитал агент) и `assumption` (принято без данных
  проекта). Это ось словаря, а не второй примитив: разметка, тон и правило
  акцента те же. `assumption` дополнительно несёт точку-маркер — допущение
  должно быть видно взглядом, а не вчитыванием. Оба вида показаны на
  `/proba/system` блоком «Пометки».

Что этот экран добавил к списку «легко сломать обратно»:

- **Раскрытие — одно множество на весь экран, но замена значения адресная.**
  Аккордеонов на экране столько же, сколько помещений, плюс внешний. Значение
  каждого — срез общего множества (`open`), а `setOpen(keys, scope)` заменяет
  только ключи своего списка: без `scope` раскрытие секции в одном помещении
  схлопывало бы соседнее.
- **Ключ секции составной.** `{локальный id помещения}::{ключ секции}` —
  «Геометрия» на экране столько же, сколько помещений, и по одному
  `section.key` они бы слиплись в один элемент аккордеона.
- **«Далее» раскрывает пару.** Секция внутри свёрнутого помещения не видна,
  поэтому навигация всегда открывает помещение вместе с целью.
- **Экспандер умолчаний целью навигации не бывает.** Принятое видно сводкой без
  клика; вести туда «Далее» значило бы обещать работу, которой нет.
- **`min`/`max` поля в контрол не уходят.** Границы предупреждают, а не
  запрещают: зажатый `NumberField` не дал бы ввести спорное число, и подпись
  «! проверить» стала бы недостижимой.
- **Слов «Далее» и «Условия расчёта» в схеме `KeoEditor` нет.** Пока экран в
  песочнице, они стоят константами (`keo-next-label.ts`,
  `keo-conditions-label.ts`); при переносе в пакет схеме понадобятся свои поля
  — у `LiftEditor` это уже сделано (`pendingLabel`).

## Из чего собран `/proba/report-assembly`

Третий экран — не редактор: отчёты read-mostly, состояния у них почти нет, вся
интерактивность — кнопки-действия. Интересны они другим: бьют ровно в слепые
зоны набора. Строка списка, двухчастный чип, статусная пилюля с точкой,
serif-заголовок, таблица с итогом, заметка на утопленном фоне и карточка
протокола — ни одного из них в наборе не было.

**Экраны больше не живут здесь.** Они переехали в пакет вместе с рендерерами
`ThermalReportNext` и `LiftReportNext` (change `reports-next`), и страница
импортирует их оттуда — второй экземпляр разошёлся бы с рендерером первой же
правкой:

```ts
import {ThermalReportNextScreen} from '../../../../packages/catalog-react/src/renderers/thermal-report-next-screen';
import {LiftReportNextScreen} from '../../../../packages/catalog-react/src/renderers/lift-report-next-screen';
```

```
ReportBlock × 3            теплотех (одна конструкция) · теплотех (список) · лифты
  ThermalReportNextScreen / LiftReportNextScreen   экран из пакета; вместо dispatchAction — консоль
    Card                   карточка-рама сообщения
      ReportNextVerdictSection   StatusPill size=badge + ReportHeadline (display + serif) + подстрока
      ReportNextSection          подпись-оверлайн и строки: «Проверки» / «Конструкции» / «Что изменить»
        ReportRow                Card + слот main (титул + пояснение) и слот side
          StatusPill             статус проверки, чип отклонения, статус варианта
          Button outline         «Подобрать» · «Пересчитать»
      ReportNote                 допущения расчёта
    ThermalReportNextLayers      Card + ReportTable: скролл в своём контейнере, итог R₀
    ReportNextInputsCard         Card + группы DataChip, пунктирные у tone: 'warning'
      ReportNote                 оговорка группы
    ReportNextProtocolCard       ReportProtocolCard: лейбл, мета и «Скачать ⌄» — без раскрытия
      Menu side="top"            форматы .md / .docx, попап растёт вверх
```

Три отчёта стоят на одной странице без переключателя намеренно: переключать у
read-mostly экранов нечего, а ценность в том, чтобы видеть их одновременно.
Сравнение «было / стало» живёт в демо-треде, где старый и новый рендерер
получают одно наполнение.

Наполнение — валидные фикстуры каталога (`thermal-report-single.json`,
`thermal-report-multi.json`, `lift-report.json`), разобранные схемами
компонентов: JSON и типы разъезжаются молча, а `parse` роняет страницу на
первом расхождении.

Из четырёх секций лифтового отчёта три — те же компоненты, что у теплотеха:
вердикт, исходные данные и протокол написаны один раз. Своё у лифтов только
«Что изменить», у теплотеха — проверки, конструкции и таблица слоёв.

Семь примитивов, которых для этих экранов не хватило, переехали в пакет
вместе с экранами и показаны на `/proba/system` блоком «Отчёт»:

- **`ReportRow`** — строка списка со слотами `main` и `side`. Одна и та же в
  трёх блоках двух отчётов; рамку и фон даёт `Card`, строка добавляет только
  раскладку двух слотов и акцентную рамку рекомендованного варианта.
- **`DataChip`** — двухчастная пилюля «label value» исходных данных. Формой
  это `Chip` набора, новые оси — две части и пунктир («принято системой»).
- **`StatusPill`** — точка + слово, тона `pass` / `fail` / `warning` /
  `neutral`. Вердикт и статус строки — одна пилюля с осью кегля, а не два
  примитива: `a2ui-tr__badge` и `a2ui-tr__status` различались только кеглем.
  Четвёртой ступени шкалы под вердикт не заводится — он стоит на `sub` с
  модификатором `overline`.
- **`ReportHeadline`** — заголовок вердикта. Ступень `display` у него уже
  была, недостающее — семейство, поэтому это **ось `serif` существующей
  ступени** (`--a2ui-font-serif` в слое токенов), а не четвёртая ступень.
- **`ReportTable`** — колонки, числа справа табличными цифрами, итоговая
  строка на утопленном фоне, скролл внутри своего контейнера. Таблицы в наборе
  не было вовсе; `renderers/simple-table` не годится — это компонент A2UI со
  своим хостом и своими инлайн-стилями мимо слоя токенов.
- **`ReportNote`** — заметка с точкой-маркером на утопленном фоне: допущения
  расчёта и оговорка группы исходных данных.
- **`ReportProtocolCard`** — строка протокола: лейбл, мета и слот действия.
  Раскрытия нет, поэтому нет и шеврона.

Кнопки переписывать не пришлось: `Button` (`filled` / `outline` / `link`)
закрывает все виды кнопок отчётов. «Скачать» оказалось почти `Menu` набора:
не хватило одной оси — стороны попапа. Протокол стоит последней карточкой, и
список, растущий вниз, вылезает за нижний край сообщения, поэтому у `Menu`
появилась ось **`side`** (`side="top"`), а не отдельный компонент.

## Технические решения, которые легко сломать обратно

- **Токены объявляются одним слоем.** `proba-tokens.ts` — единственное место со
  значениями; в правилах примитивов литералов цвета и кегля нет, только
  `var(--a2ui-*)`. Поверхность перекрашивает слой у себя на корне.
- **Попап объявляет токены сам.** Он уезжает в портал (`closest('#root') === null`)
  и наружного слоя не видит. Набор попапа не переписан руками, а отфильтрован из
  общего слоя (`declareTokens(POPUP_TOKEN_NAMES)`) — разойтись значениями нечем.
- **Уровень карточки считает CSS, не пропс.** `.a2ui-card .a2ui-card` делает
  вложенную карточку утопленной и радиусом 10. Глубже второго уровня фон
  возвращается на светлый — стопка утопленных прямоугольников не читается.
- **Контейнер раскладки один — корень набора.** `container-type` объявлен на
  `.a2ui-kit`, как у нынешнего `ConstructionsEditor` на `.a2ui-ce`; форма своей
  обёртки не заводит и просто растягивается по месту. Мерить по самой форме
  соблазнительно, но она уже внутри отступов карточки и её тела — это ~60px, и
  порог, замеренный по ней, отсекал бы вторую колонку раньше, чем нужно.
  Числа — `FORM_TWO_COLUMNS_AT` = 500 и `FORM_THREE_COLUMNS_AT` = 620.
- **У кнопки нет своего `font-size`.** `md`/`lg` берут ступень `body`, `sm` —
  `sub`. Иначе кнопка тихо становится четвёртой ступенью шкалы.
- **Кнопку не верстать руками.** Раскрывашка — это `Accordion.Trigger` или
  `Collapsible.Trigger` с классом от `buttonClassName({variant: 'link'})`;
  `a2ui-card__title` даёт ему только место в строке.
- **Состояние раскрытия не ходит пропсом.** Шеврон поворачивает CSS по
  `data-panel-open`, который вешает библиотека. Пропс `open` рассинхронизировался
  бы с панелью.
- **`aria-controls` объявляем сами.** Base UI снимает его со свёрнутого триггера,
  поэтому id панели задан явно (`proba-conditions-panel`, `proba-construction-*`).
  На странице лифтов id несёт ещё и ветку (`proba-lift-per-lift-building`): веток
  на ней две, и «Здание» на странице два — без ветки обе кнопки указывали бы в
  одну панель.
- **Заголовок секции не переносится.** В узком контейнере он делил строку со
  сводкой поровну и рассыпался на «Ли / фт / 2»: у `.a2ui-card__title` дети
  сжимаются одинаково. Место уступает сводка — она длиннее и переносится
  осмысленно.
- **Попап открыт, только когда ему есть что сказать.** `open` контролируемый:
  `loading || queried || options.length > 0`. Иначе на первую букву под полем
  висит пустая коробка в пару пикселей. «Ищем…» видно всю паузу debounce —
  `loading` поднимается с момента прохождения порога, а не в момент запроса.
- **Удаление живёт в меню, а не голым «✕».** Необратимое действие не должно
  попадаться под палец так же легко, как раскрытие; меню приносит клавиатуру и
  роли даром.
- **Выбор опции ловится причиной события.** `onValueChange(value, {reason})`,
  `reason === 'item-press'`; `onClick` на `Autocomplete.Item` — недокументированный
  контракт.
- **В JSX нет `cond ? (<…>) : null`.** Каждая ветка — отдельный компонент с
  ранним `return null`: `ConditionsSummary`, `ConstructionTypeRow`, `ButtonIcon`,
  `LookupOptionSlot`.
- **Протокол не раскрывается, и шеврона у него нет.** Раскрывашку завели
  было ради `content`, но краткий вывод в чате не читают построчно, а
  простыня всё равно уезжает файлом; шеврон обещал бы содержимое, ради
  которого строку не открывают.
- **Меню «Скачать» растёт вверх.** Протокол — последняя карточка отчёта, и
  попап вниз вылезает за край сообщения, то есть за край треда.
- **Модификатор примитива объявляется двумя классами.** `a2ui-chip--data`,
  `a2ui-chip--dashed` и `a2ui-card--accent` доливаются поверх правил
  собственного примитива (`.a2ui-kit .a2ui-chip.a2ui-chip--data`): при равной
  специфичности победил бы порядок слоёв набора, а он зависит от того, какой
  слой объявлен раньше в `KitStyles`.

## Что выяснилось про Base UI 1.7 по ходу

- **У `Accordion` больше нет стрелок между заголовками.** Роящий фокус убран
  вслед за обновлением APG (w3c/aria-practices#3434): каждый заголовок стоит в
  порядке `Tab`, раскрывает `Enter`/`Space`. `loopFocus` и `orientation` помечены
  deprecated и на клавиатуру не влияют.
- **`NumberField` — это не `spinbutton`.** Поле рендерится `input type="text"` с
  `aria-roledescription="Number field"`; `role`/`aria-valuenow` библиотека не
  ставит. Стрелки `↑`/`↓` и кнопки ступеней работают, подписи у кнопок
  английские — задаём свои.
- **У `Autocomplete` нет `itemToStringLabel`.** В поле уходит результат
  `itemToStringValue`, поэтому туда отдаётся `label`, а настоящий `value` живёт
  скрытым полем — как в нынешнем `LookupCombobox`.
