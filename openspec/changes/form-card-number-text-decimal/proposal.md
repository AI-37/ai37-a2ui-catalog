# FormCard: number-поля как text с десятичным вводом

## Why

FormCard-рендерер (`@ai37/a2ui-catalog-react`) рисует `field.type === 'number'`
как `<input type="number">` **без `step`**. По умолчанию HTML `step=1` → инпут
валидирует только целые: дробное значение отвергается браузером.

Симптомы (живой UI, поле «Vn — скорость, м/с»):
- ввод `2,5` (запятая) → «Enter a number» (number-input не понимает запятую);
- ввод `2.5` (точка) → «Enter a valid value» (нарушает `step=1`).

Для лифтовых расчётов дробные значения нормальны (Vн=1,6; hf=3,3; Q-коэф.).
Агент уже умеет коэрсить ввод: `coerceFormValues` парсит `'2,5'`/`'2.5'` → 2.5
(`.replace(',', '.')` + `Number`). Значит проблема чисто в рендере: жёсткий
`type=number` мешает там, где источник истины по числу — агент.

## What Changes

В рендерере FormCard (`packages/catalog-react/src/renderers/form-card.tsx`):

- `field.type === 'number'` рендерить как `<input type="text">` с
  `inputMode="decimal"` (мобильная цифровая клавиатура) вместо `type="number"`.
- Принимать и точку, и запятую как десятичный разделитель — нормализацию
  (`,`→`.`, в число) делает **агент** (`coerceFormValues`), рендер шлёт строку
  как есть.
- select/boolean/text — без изменений.

## Impact

- Затрагивает только `catalog-react` рендерер FormCard (один `<input>`-бранч).
- Схема (`catalog-schemas`) НЕ меняется — `field.type:'number'` остаётся в
  контракте; меняется лишь способ рендера (HTML-инпут), агентский коэрс уже есть.
- Теряется нативный number-spinner (стрелки ↑↓) — приемлемо: для рядов (Q,
  doorWidth) используется select, а свободные числа (Vn, hf) вводятся текстом.
- **Non-goals:** валидация диапазонов (это на агенте); другие компоненты;
  ChoiceCard; схемы Zod/JSON.
