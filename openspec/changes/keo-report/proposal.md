# KeoReport: карточный результат расчёта КЕО

## Why

Результат расчёта КЕО (вердикт «соответствует / не соответствует», варианты
исправления, исходные данные, протокол по ГОСТ Р 21.514) без компонента
уйдёт в чат markdown-простынёй — та же проблема, что решал ThermalReport
для теплотехники. Согласован макет карточного вывода; в каталоге компонента
нет.

## What Changes

- **Новый компонент каталога `KeoReport`** (аддитивно, v2) по канону
  ThermalReport (включая ревизию thermal-report-standard-buttons):
  вердикт, рекомендации, результаты по помещениям, исходные данные,
  протокол одной строкой со «Скачать».
- **Секция «Что изменить» — карточки рекомендаций** `[{title, detail,
  tone: 'success'|'neutral'|'fail', action?}]`: вариант с кнопкой пересчёта
  («Пересчитать с окном 1,8 × 1,5» — dispatchAction с payload), нейтральный
  вариант-пояснение, отвергнутый вариант (detail красным, без кнопки).
  Такой секции нет ни в одном компоненте каталога — это главное отличие от
  ThermalReport.
- **Результаты по помещениям** (опционально, при N > 1): строки
  `{name, value, norm, status, action?}` — аналог списка конструкций TR.
- **Исходные данные** — группы чипов с тонами normal/warning
  («из проекта» / «принято системой — проверьте») и note — как в TR.
- **Протокол расчёта** — неразворачиваемая строка (лейбл + meta +
  «Скачать» клиентским Blob'ом), канон после
  thermal-report-standard-buttons. Содержимое скачиваемого файла — состав
  таблиц А.1/Б.1/Б.2 ГОСТ Р 21.514 — формирует агент.
- **Нормативные правки относительно макета**: подпись протокола —
  «формулы СП 367.1325800» (математика расчёта — СП 367, а не СП 52;
  СП 52 даёт только C_N/MF/e_н); источник нормы e_н в вердикте — строка из
  props (эталон модуля — СП 52 Прил. Л). Логика вердикта, включая допуск
  −10 % (СП 367 п. А.2.12), — на агенте: компонент получает готовый статус.
- Все значения — готовые строки (десятичная запятая, «%», «м»);
  кнопки — канон CE-кнопок (не перекрашиваются хостом).
- Фикстуры valid/messages (pass и fail наполнения), демо, тесты.

## Capabilities

### New Capabilities

- `keo-report`: контракт компонента — схема props, вердикт со статусом,
  карточки рекомендаций с действиями, результаты по помещениям, группы
  исходных данных с тонами, протокол-строка со скачиванием.

### Modified Capabilities

_(нет)_

## Impact

- `packages/catalog-schemas`: `components/keo-report.ts` + регистрация;
  export:public.
- `packages/catalog-react`: `renderers/keo-report*.tsx/.ts` (паттерн
  thermal-report: verdict/recommendations/rooms/inputs/protocol), группа
  токенов `kr`, регистрация.
- `packages/catalog-python`: зеркальная модель + parity-тест.
- `fixtures/*`, `apps/demo`, `tests/react`; version bump + CHANGELOG.
- Потребители: будущий агент КЕО (эмит + обработка `report_*`-действий),
  spai-ui bump.
- **Non-goals**: markdown-рендер протокола в UI; расчёт вариантов «что
  изменить» на клиенте; передача файла через транспорт (только клиентский
  Blob, как у TR).
