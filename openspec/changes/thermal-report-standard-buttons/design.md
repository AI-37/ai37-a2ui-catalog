## Context

Стили термо-отчёта (`thermal-report-styles.ts`) уже объявляют кнопки «по
канону CE» (метрики совпадают), но в хостовом чате кнопки всё равно выглядят
чужими: хост объявляет свои правила на элементе (`[data-copilotkit] button`,
`.a2ui-surface button:hover` — серая пилюля с заливкой и рамкой), а TR, в
отличие от CE, не объявляет собственных hover/фокус-переопределений — есть
только `.a2ui-tr-btn--link:hover`. CE решает это явным блоком «ховер
объявляем сами» (`constructions-editor-styles.ts:219-255`).

Протокол расчёта сейчас — нативный `<details>` со сводкой и раскрываемым
`content`; по новым требованиям он должен стать одной неразворачиваемой
строкой (лейбл + meta + «Скачать»).

## Goals / Non-Goals

**Goals:**

- Кнопки TR неотличимы от кнопок CE/lift-editor в хосте: outline-пилюля,
  solid как `--commit`, ссылки без рамки с подчёркиванием на ховере.
- Протокол — одна строка без `<details>`, скачивание сохраняется.

**Non-Goals:**

- Общий разделяемый CSS/компонент кнопки между TR и CE — каждый рендерер
  остаётся самодостаточным (существующий инвариант каталога).
- Изменения схемы `thermal-report.ts` (`protocol.*` остаётся как есть) и
  контракта диспатча действий.

## Decisions

1. **Зеркалим канон CE внутри TR-стилей, а не импортируем CE-классы.**
   Рендереры каталога изолированы (свой префикс, свой инжект стилей);
   переиспользование `a2ui-ce-*` в TR связало бы компоненты. Копируем
   значения (padding 8/14, radius 9, font 13/13, `--solid` = `--commit`) и
   блок hover-переопределений: `.a2ui-tr .a2ui-tr-btn:hover { background:
   transparent; border-color: <muted>; }`, `--solid:hover` сохраняет
   заливку, `--link:hover` — только подчёркивание. При необходимости
   перебить хостовые правила на элементе — поднять специфичность тем же
   приёмом, что CE (двойной класс/`:where`-свободные селекторы), и явно
   обнулить рамку/фон у ссылок.
2. **Протокол — обычный `<div>`-ряд вместо `<details>/<summary>`.** Лейбл,
   meta и «Скачать» в одну строку (как текущий summary, но без шеврона и
   курсора-указателя на строке). Обработчику скачивания больше не нужны
   `preventDefault`/`stopPropagation` (нет родительского summary). Стили
   `a2ui-tr__protocol-content` и связанные с раскрытием — удалить.
3. **Проверка — скриншотами в headless Chrome в хостовом окружении**
   (demo-приложение эмулирует хостовые правила? если нет — добавить в
   demo хостовые правила-имитации `.a2ui-surface button` рядом с уже
   существующей практикой), т.к. баг воспроизводится только под хостовыми
   стилями, зелёные jsdom-тесты его не ловят.

## Risks / Trade-offs

- [Хостовые правила могут оказаться специфичнее, чем видно из комментариев
  CE] → свериться с реальным DOM хоста при проверке скриншотами; CE уже
  выигрывает эту войну — использовать ровно его специфичность.
- [Удаление раскрытия протокола прячет краткий вывод `content` из UI] →
  осознанное решение пользователя; `content` остаётся fallback-содержимым
  скачивания при отсутствии `downloadContent`.
- [Дрейф канона: значения CE скопированы, не разделены] → комментарий-якорь
  в обоих файлах стилей («канон CE», уже принятая практика в TR).
