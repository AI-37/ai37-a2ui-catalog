## Why

Карточка конструкции показывает зелёное «готова» там, где расчёт невозможен.
Живой стенд теплотеха 2026-09-14: конструкция «Пол 1 этажа, перекрытие над
подвалом» без выбранной разновидности — чип «готова», рядом `Rпр 5.95 ≥ 3.29`
зелёным, а «Рассчитать» возвращает в чат «выберите подтип перекрытия» и отчёт
не собирается. Пользователь жмёт «Рассчитать» по кругу: в списке из 8
конструкций не видно, какая мешает.

- **4 причины** невалидности в `find-invalid-layers.ts`: нет λ, нет
  положительной толщины, пустое название материала, нет паспортного Rпр.
  Незаполненной разновидности среди них нет — отсюда «готова».
- **1 тип из 6** имеет разновидность, и она выбирает αн по таблице 6 СП 50:
  чердак 12 / подвал с продухами 17 / невентилируемый подвал 6 / пол по грунту
  — без члена 1/αн. Разброс втрое, поэтому без неё Rпр не считается.
- **Число в зелёном чипе условно.** Без разновидности агент берёт αн = 17 с
  пометкой `(доп)` — «наименьший вклад 1/αн, в запас». Карточка показывает
  уверенный результат там, где он на допущении.
- **Сигнал уже есть в контракте.** `constructionTypeConfigSchema.alphaN` —
  `number | Record<subtype, number>`, и агент шлёт запись ровно тому типу, у
  которого разновидность обязательна (`construction-type-configs.ts:53`).
  Компонент этот сигнал не читает.
- **Подсветка уже написана.** `cardClassName({invalid})` красит рамку
  `--a2ui-card-danger` (`#dc2626`), чип показывает «проверить». Так сегодня
  выглядит слой без толщины — приделывать нечего, надо лишь включить.
- **Место под текст тоже есть.** Шапка раскрытой карточки печатает
  разновидность через «·» (`constructions-next-header-summary.tsx:24`); когда
  её нет, строка не выводится вовсе, и место остаётся пустым. Подсветка без
  текста говорит «что-то не так», но не говорит что.

## What Changes

`findInvalidLayers` получает пятую причину — **тип, у которого αн задан записью
по разновидностям, а разновидность не выбрана**:

```ts
const subtypeRequired = typeof config?.alphaN === 'object';
const missingSubtype = subtypeRequired && entry.subtype === undefined;
```

Признак входит в `invalid` и обнуляет `missingLambdaCount`: иначе чип соврёт
«N слоёв без λ» при полностью заполненных слоях.

Карточка получает красную рамку и чип «проверить» уже существующим путём, у
обоих семейств рендереров сразу.

**Шапка раскрытой карточки называет, чего не хватает.** Там, где печаталась бы
разновидность, при её отсутствии выводится «разновидность не выбрана» —
предупреждающим цветом, тем же приёмом, что «толщина не задана» в строке слоя
(`constructions-next-layer-numbers.tsx:22`). Нового примитива не нужно: текст
встаёт на место значения.

**Правило не зашивается в клиент.** Обязательность разновидности выводится из
конфига типа, который присылает агент, — той же механикой, которой уже
выводится обязательность паспортного Rпр из `hasLayers`.

## Impact

- `packages/catalog-react/src/renderers/find-invalid-layers.ts` — причина и
  поле результата.
- `packages/catalog-react/src/renderers/constructions-next-header-summary.tsx` —
  текст вместо пустого места.
- `tests/react/` — сценарии из `specs/`.
- **Не трогается:** схема props, Python-зеркало, `spai-chat-backend`, агент.
  Контракт не меняется, перекатывать потребителей схемы не нужно.
- **Потребитель** — `spai-ui` (рендерит). На стенде включён
  `ConstructionsEditorNext` (`CONSTRUCTIONS_EDITOR_NEXT=true`) — текст кладётся
  в него.
- **Версия пакетов** поднимается тем же PR (`REVIEW.md:16`).
