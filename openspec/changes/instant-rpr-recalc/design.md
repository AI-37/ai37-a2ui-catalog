## Context

Чип Rпр в шапке карточки считается `computeLiveRpr(entry, config, condition)`
из закоммиченного `entry` (`constructions-editor-card.tsx`). Черновик правки
слоя живёт в локальном state `LayerForm`
(`constructions-editor-layer-row.tsx`) и наверх поднимается только по
«Применить»; то же у `PassportForm`. Это осознанное решение
constructions-editor-inline-layer-edit: «ввод внутри незакоммиченной формы
наверх не поднимается вовсе» — оно же и делает чип «слепым» к правкам.

Одновременно во всём редакторе раскрыта не более чем одна форма
(`editingTarget` в `constructions-editor.tsx`), значит превью-черновик — это
максимум один слой (или одно паспортное значение) на весь редактор.

## Goals / Non-Goals

**Goals:**

- Чип Rпр карточки реагирует на каждое изменение полей открытой формы слоя
  (edit и new) и формы паспортного Rпр — без «Применить».
- «Отмена», переключение формы, закрытие карточки — чип возвращается к
  значению из закоммиченного состояния.
- Ни схема props, ни payload'ы action'ов/черновиков не меняются.

**Non-Goals:**

- Live-реакция сводки «проходит N из M» в футере и статусных чипов/подсветки
  невалидности — они остаются на закоммиченном состоянии (см. Решение 3).
- Форма шапки карточки (тип/subtype/название): смена типа меняет и config, и
  Rнорм — превью там отдельная задача, сценарий подбора не про неё.
- Изменения канонического серверного расчёта.

## Decisions

### Решение 1: черновик поднимается только до карточки, как превью

`LayerForm` получает необязательный колбэк `onDraftChange(draft)` и зовёт его
при каждом `setDraft`. Карточка держит `previewLayer` в state и строит
превью-entry для чипа: для `edit` — `layers` с подменённым слоем по индексу,
для `new` — `layers` с добавленным в конец; `PassportForm` аналогично
поднимает `rprPassport`. Чип получает `computeLiveRpr(previewEntry, …)`.

Альтернатива — поднять весь черновик в редактор (как `editingTarget`) —
отвергнута: редактору черновик не нужен (футер остаётся на закоммиченном,
Решение 3), а канал «каждое нажатие клавиши через два уровня» шире
необходимого. Альтернатива «считать Rпр внутри формы и показывать рядом» —
отвергнута: пользователь смотрит на чип в шапке, дублирующее число рядом с
формой плодит два Rпр на экране.

### Решение 2: жизненный цикл превью привязан к `editingTarget`

Превью в карточке сбрасывается (`null`) при любом изменении `editingTarget`:
открытие/закрытие/переключение формы, «Отмена», коммит. После коммита
закоммиченный `entry` уже содержит те же значения — скачка чипа нет. Пока
превью `null` (форма только открыта, правок не было), чип считается из
закоммиченного `entry` — открытие формы само по себе ничего не меняет.

### Решение 3: превью — только чип Rпр

Статусные чипы, подсветка невалидности, строки-сводки, футер «проходит N из
M» и черновики агенту продолжают жить от закоммиченного состояния. Причины:
инвариант «форма правит копию» остаётся правдой для данных; невалидность,
мигающая на полуввёденном числе, — шум; футер за пределами карточки не видит
превью и не должен (см. Решение 1). Незакоммиченные-но-валидные значения уже
сегодня отбрасываются переключением формы — превью этого не меняет.

### Решение 4: неполный черновик деградирует так же, как неполный слой

`computeLiveRpr` уже пропускает слои без положительной толщины или λ —
превью с очищенным полем просто временно исключает слой из суммы (чип
уменьшается), без спец-обработки NaN/пустых строк.

## Risks / Trade-offs

- [Чип «дышит» на промежуточном вводе: стёр «250», набираешь «300» — на «3»
  Rпр прыгнет] → это честная мгновенная обратная связь, ровно за ней превью и
  затевалось; без дебаунса, ввод локальный и дешёвый.
- [Расхождение чипа и футера: чип уже видит черновик, «проходит N из M» —
  нет] → осознанный компромисс Решения 3; расхождение живёт только пока
  открыта форма, коммит их сводит.
- [Тест «Ввод в форме не трогает live-Rпр» закреплял обратное поведение] →
  тест переворачивается вместе с требованием (delta-спек
  constructions-editor-inline-layers), это не регрессия, а смена контракта.
