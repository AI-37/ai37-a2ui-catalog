## Решения

### 1. Вид слоя — явный селектор, а не только спец-запись справочника

До этого вид ставился одним путём: выбором «Вентилируемый зазор» / «Замкнутый
зазор» из lookup материалов, а `kind` проставлял агент после submit. Для
тонкого слоя это не работает: у него есть СВОЁ название («Адгезивный слой»,
«Биполь ЭПП»), и заменять его записью «Тонкий слой» — терять состав. Поэтому
вид — отдельное поле строки (`Select` набора), название остаётся свободным.
Решение владельца (2026-09-24): «добавить ещё один вид слоя и в каталоге для
каждого слоя показывать, какой это вид».

Спец-записи справочника остаются для совместимости и ставят тот же `kind`
при выборе (`layerKindFromOption`) — два входа в одно поле, а не два поля.

Цена: форма слоя из трёх полей стала четырьмя; в широком контейнере материал
занимает строку, вид/толщина/λ — вторую.

### 2. Смена вида на не-материал снимает λ и ключ справочника

Оставить `materialKey` у зазора — прислать агенту строку прил. М под видом
зазора; агент читает ключ раньше вида (`resolveEditorLayer`) и сочтёт слой
материалом. Поэтому селектор чистит `materialKey`, `lambdaA/B`,
`lambdaManual`. Обратно на «Материал» поля не восстанавливаются — λ вводится
заново или приходит с опцией.

### 3. Толщина у `vent-gap` и `thin` не нужна, у `closed-gap` — нужна

Зеркало серверного `layerNeedsThickness`: Rs замкнутой прослойки берётся из
табл. Г.1 по δ, вентилируемая отбрасывается с наружными слоями, тонкий даёт
Rs = 0. Клиентская валидация (`find-invalid-layers`) не-материалы и раньше не
проверяла; менялась только подпись.

### 4. Прежний `ConstructionsEditor` не трогается

`isGap = kind !== 'material'` там читает `thin` как зазор — не падает, λ не
просит. Селектора вида у него не будет: рендерер под замену, prod на `*Next`
(`PROD_APP_CONSTRUCTIONS_EDITOR_NEXT=true`).

## Открытые вопросы

- Нужен ли `thin` в демо-справочнике `apps/demo` — нет: демо-lookup отдаёт
  только материалы, спец-записи живут у агента.
