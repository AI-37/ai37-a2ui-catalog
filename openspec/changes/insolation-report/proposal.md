# InsolationReport: карточный результат расчёта инсоляции

## Why

Результат расчёта инсоляции — вердикт по СанПиН, суточный график
солнце/тень, проверки (суммарная продолжительность, максимальный
непрерывный период) — без компонента уйдёт markdown-простынёй. Согласован
макет; ключевой элемент (таймлайн инсоляции) в каталоге отсутствует.

## What Changes

- **Новый компонент каталога `InsolationReport`** (аддитивно, v2) по канону
  отчётов (ThermalReport + предложенный KeoReport): вердикт, проверки,
  исходные данные, протокол-строка со «Скачать».
- **Таймлайн инсоляции** — новый визуальный элемент: горизонтальная ось
  расчётного дня с засечками, сегменты `{from, to, kind: 'sun'|'shadow',
  label?}` (минуты — единственные числа в схеме, нужны для пропорций),
  заголовок («ИНСОЛЯЦИЯ 22 АПРЕЛЯ · 8:00–16:00»).
- **Проверки** `[{title, detail, status: 'pass'|'fail'|'info', action?}]`:
  продолжительность (с указанием ветви прерывистой инсоляции), максимальный
  непрерывный период; проверка-ссылка «По квартире — считается на уровне
  проекта» с action «Посчитать по проекту» (dispatchAction).
- **Пояснительные плашки** (`assumptions`): применённая ветвь прерывистой
  инсоляции, «учтено одно здание из вопроса — сверьте с генпланом».
- **Исходные данные** — группы чипов с тонами normal/warning + note,
  кнопка «Изменить и пересчитать» (канон отчётов).
- **Протокол** — неразворачиваемая строка («солнечная геометрия · N
  шагов») + «Скачать» клиентским Blob'ом.
- Вся нормативная логика (нормы зоны, ветвь прерывистой инсоляции, допуски)
  — на агенте; компонент получает готовые строки и статусы. Нормативные
  строки фикстур — сверить с СанПиН 1.2.3685-21 (выписок в проекте нет).
- Фикстуры (pass/fail), демо, тесты.

## Capabilities

### New Capabilities

- `insolation-report`: контракт компонента — схема props, вердикт,
  таймлайн солнце/тень с пропорциональными сегментами, проверки со
  статусами и действиями, группы исходных данных, протокол-строка.

### Modified Capabilities

_(нет)_
