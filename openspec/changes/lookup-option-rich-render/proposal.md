## Why

Опция подсказки lookup'а — это одна строка `label`, склеенная сервером. Для
справочника материалов прил. М СП 50 (теплотехнический агент) сервер вынужден
паковать в неё сразу три разнородные вещи — раздел справочника, название
позиции и числа — и пользователь видит нечитаемое:

```
Глиняного обыкновенного на цементно-песчаном растворе (ρ 1800) — λА 0,7 / λБ 0,81
```

Прилагательное без существительного (существительное — в разделе табл. М.1
«Кирпичная кладка из сплошного кирпича», который в одну строку уже не влез),
числа, забивающие название, и никакого указания, чем именно эта опция ответила
на запрос. При выдаче в 8–10 позиций одного семейства строки различаются
только плотностью в середине текста — глазами это не сканируется.

Вторая половина проблемы — **дропдаун закрыт, пока летит запрос**: попап
рендерится по `options.length > 0`, поэтому между вводом символа и ответом
(debounce + сеть) поле выглядит так, будто справочник ничего не нашёл.
Пользователь дописывает следующий символ поверх ещё не пришедшего ответа.

Обе беды — про отображение: данные у клиента уже есть или уже едут, компонент
их не показывает.

## What Changes

- **Опция может нести три необязательных слота оформления** — `group`
  (надстрочный контекст), `title` (основная строка), `meta` (приглушённая
  нижняя строка). Имена нейтральны: для материалов это «раздел М.1 · название
  позиции · ρ и λ», для городов — «регион · город · климат».
- **Многострочный рендер опции** вместо одной строки: group сверху мелким
  приглушённым, title — основной строкой, meta — снизу приглушённым.
- **Обратная совместимость**: опция без `title` рендерится ровно как сейчас —
  одной строкой `label`. `label` остаётся обязательным и самодостаточным.
- **Подсветка совпадения**: вхождение текущего ввода подсвечивается жирным в
  каждом слоте. Считается на клиенте, разметка с сервера не принимается.
- **Состояние загрузки**: попап открыт с момента, как ввод прошёл порог
  `minChars`, и показывает «Ищем…» до ответа; завершившийся запрос без опций
  показывает «Ничего не найдено». До первого запроса попапа нет — как сейчас.
- **a11y**: статус-строка не является опцией списка (`role="status"` вне
  `<ul role="listbox">`), на попапе — `aria-busy` во время загрузки.
- Изменение задевает **обе поверхности сразу**: `LookupCombobox` общий у
  lookup-поля `FormCard` и у строки слоя `ConstructionsEditor`.

## Capabilities

### New Capabilities

- `lookup-option-rich-render`: многострочная опция из необязательных слотов
  `group`/`title`/`meta`, fallback на `label`, подсветка совпадения,
  состояния «загрузка» и «ничего не найдено».

### Modified Capabilities

- `form-card-lookup-fetch-mode`: хук fetch-канала дополнительно сообщает
  состояние запроса (`loading`, «запрос уже был») — без него компонент не
  может отличить «ещё не искали» от «искали, пусто» и показать загрузку.

## Impact

- `catalog-schemas`: `form-card-lookup.types.ts` — необязательные `group` /
  `title` / `meta` в `LookupOption`. Тип wire-уровня, не zod-схема props:
  `.strict()`-объектов и python-зеркала не касается.
- `catalog-react`: `lookup-combobox.tsx` (многострочный рендер, подсветка,
  статус-строка), `lookup-combobox.types.ts`, `use-lookup-suggest.ts`
  (`loading` / `queried`), `parse-lookup-options.ts` (тест на сохранность доп.
  полей).
- `catalog-python`: без изменений (props те же).
- Демо `apps/demo`: пример справочника с заполненными слотами.
- Потребители: `spai-thermal-calc-agent` — чтобы слоты приехали, агент должен
  начать их отдавать (раздел табл. М.1 в `lambda-m`, отдельная работа в его
  репозитории); до тех пор рендер деградирует в текущий однострочный.
  `spai-ui` — без изменений.
- **Non-goals**: клавиатурная навигация по опциям (↑/↓/Enter — отдельный
  change, сейчас выбор только мышью); ранжирование и состав выдачи (сервер);
  опция «Использовать „X“ как есть» и пользовательские материалы (агент);
  виртуализация длинных списков.
