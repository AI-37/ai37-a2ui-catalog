## MODIFIED Requirements

### Requirement: Хук fetch-канала сообщает состояние запроса

Хук подсказок fetch-канала SHALL, помимо списка опций, сообщать состояние
запроса: идёт ли поиск и был ли уже завершённый запрос по текущему вводу.
Состояние «идёт поиск» SHALL подниматься в момент, когда ввод достиг порога
`minChars`, — то есть включая паузу debounce, а не только время сетевого
запроса. Отмена предыдущего запроса следующим вводом SHALL NOT гасить
состояние «идёт поиск». Прежнее поведение канала — debounce, порог `minChars`,
отмена in-flight запроса через `AbortController`, тихий fallback на пустой
список при любом сбое — SHALL остаться без изменений.

#### Scenario: Поиск виден в течение debounce

- **WHEN** ввод достиг порога, а таймер debounce ещё не истёк
- **THEN** хук сообщает «идёт поиск»

#### Scenario: Быстрый набор не гасит индикатор

- **WHEN** пользователь печатает следующий символ, отменяя предыдущий запрос
- **THEN** состояние «идёт поиск» сохраняется до ответа на последний ввод

#### Scenario: Сбой канала завершает поиск

- **WHEN** запрос завершился ошибкой сети или не-200 ответом
- **THEN** хук сообщает пустой список, «идёт поиск» снято, запрос считается
  завершённым

#### Scenario: Падение ниже порога сбрасывает состояние

- **WHEN** ввод стал короче `minChars`
- **THEN** опции пусты, «идёт поиск» снято, завершённого запроса по текущему
  вводу нет
