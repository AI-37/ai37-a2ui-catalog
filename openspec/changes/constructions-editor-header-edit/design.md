## Context

`constructions-editor-inline-layer-edit` перевёл слои на «строка-сводка ↔
единственная форма с явным коммитом», и коммит стал точкой отправки
черновика. Поля шапки карточки (тип/subtype/название) и «Rпр по паспорту»
остались на старой схеме: контролы всегда раскрыты, каждый ввод сразу мутирует
state редактора, черновик не шлётся (осознанный non-goal того change'а).

Следствия на живых карточках spai-ui:

- пользователю не видно, «сохранилось» ли: нет ни кнопки, ни отклика
  (скрины: двери, окна, кровля — «непонятно как сохранять изменения»);
- сценарий «поправил название/паспортное Rпр → пере-рендер от агента»
  теряет ввод — ровно та болячка, которую слоям уже вылечили;
- визуально шапка спорит со слоями: у слоёв аккуратные сводки, над ними —
  всегда раскрытые селект и инпут.

Вариант UX выбран пользователем: чтение с кнопкой «Изменить» + форма с
явным коммитом, паспортное Rпр — отдельный элемент того же паттерна.

## Goals / Non-Goals

**Goals:**

- Правка шапки и паспортного Rпр имеет явную точку сохранения, видимую
  пользователю, и порождает черновик.
- Раскрытая карточка читается: текст вместо постоянных контролов.
- Единая ментальная модель: «что видно в режиме чтения — то и есть state»,
  форма редактирования одна на весь редактор — любого вида.
- Схемы props, payload черновика и submit'а — прежние.

**Non-Goals:**

- Вкладка общих данных (климат/тип здания) — отдельный change.
- Debounce, черновик на ввод без коммита, блокировка submit.
- Изменения схем (`catalog-schemas`, `catalog-python`), фикстур.
- Подтверждение при потере несохранённых правок формы.

## Decisions

### Решение 1. Шапка: режим чтения + форма, как у слоя

В раскрытой карточке блок «тип + subtype + название» по умолчанию — текст:
строка типа (с разновидностью через «·») и, если задано, название вторым
рядом; рядом кнопка «Изменить». Клик открывает форму: селект типа, селект
subtype (для `cherdachnye_podval_grunt`), инпут названия, «Сохранить» /
«Отмена». Локальная копия полей — `useState` при открытии; до «Сохранить»
заголовок карточки, live-Rпр и state не меняются. «Сохранить» без изменений
равносилен «Отмене» (черновика нет).

Заголовок-аккордеон карточки продолжает показывать название из state — во
время набора в форме он не дёргается.

Альтернатива — коммит по blur каждого поля: сохраняет сегодняшний вид, но
не даёт явного «сохранено», плодит черновики на каждую перестановку фокуса
и оставляет расхождение паттернов слои/шапка.

### Решение 2. «Rпр по паспорту» — отдельный элемент того же паттерна

Для типов без слоёв значение показывается текстом («Rпр по паспорту: 0.60»,
«не задано» — предупреждающим цветом, см. подсветку невалидности) с кнопкой
«Изменить»; форма — числовой инпут + «Применить» / «Отмена». Отдельно от
формы шапки: паспортное Rпр — «данные конструкции» (аналог слоёв), а не
идентичность карточки; и правится чаще, чем тип с названием.

### Решение 3. Одна форма на весь редактор — любого вида

Состояние единственной формы в редакторе обобщается:
`editingTarget: {entryId, target: number | 'new' | 'header' | 'passport'} |
null` (сегодняшний `editingLayer` — частный случай). Открытие любой формы
закрывает текущую с отбросом правок — в том числе форму слоя при открытии
шапки и наоборот. Карточка получает свой target пропом, как сейчас.

Альтернатива — независимые формы шапки и слоя одновременно: умножает
состояния и возвращает «простыню» на карточку.

### Решение 4. Черновик — те же явные коммиты

«Сохранить» (шапка) и «Применить» (паспорт) с изменёнными полями поднимаются
как `onChange(entry, {commit: true})` — редактор шлёт черновик тем же путём,
что для коммитов слоя. Сравнение «изменилось ли» — поле-в-поле
(тип, subtype, название; паспортное Rпр), по аналогии с `layers-equal`.

## Risks / Trade-offs

- **Лишний клик на правку названия/типа** → плата за явное сохранение;
  типичный кейс правки шапки редок (чаще правят слои).
- **Потеря несохранённых правок при переключении форм** → как у слоёв:
  объём — одна форма, кнопка коммита на виду; подтверждение — вне скоупа.
- **Смена типа фиксируется только по «Сохранить»** → пока форма открыта,
  карточка живёт со старым типом (слои/паспорт не перерисовываются под
  новый тип до коммита) — это и есть «форма владеет черновиком».
- **Тесты, завязанные на всегда раскрытые селект/инпут шапки** → правятся
  вместе с change'ем.
