## Why

После `constructions-editor-inline-layer-edit` слои сохраняются явным
«Применить», а поля шапки карточки (тип/subtype/название) и «Rпр по паспорту»
по-прежнему правятся молча в локальный state: ни подтверждения, ни черновика.
На живых карточках spai-ui (двери, окна, кровля) это читается как «непонятно,
как сохранить изменения» — а сценарий «переименовал/вписал паспортное Rпр →
пере-рендер от агента» теряет ввод так же, как раньше терялась λ слоя.

Решение — тот же паттерн, что у слоёв: по умолчанию режим чтения, правка —
в форме с явным коммитом, коммит — точка отправки черновика.

## What Changes

- **Шапка карточки — режим чтения**: тип конструкции (с разновидностью) и
  название показываются текстом, рядом кнопка «Изменить». Селекты и инпут
  из раскрытой карточки уходят.
- **Форма шапки**: селект типа, селект subtype (для типа с разновидностями),
  инпут названия, кнопки «Сохранить» / «Отмена». До «Сохранить» правки живут
  только в форме: заголовок карточки, live-Rпр (α и Rнорм зависят от типа) и
  state редактора не меняются. «Сохранить» без изменений равносилен «Отмене».
- **«Rпр по паспорту» — отдельный элемент того же паттерна** (типы без
  слоёв): значение текстом + «Изменить», форма с числовым инпутом и кнопками
  «Применить» / «Отмена».
- **Форма одна на весь редактор — теперь любого вида**: формы слоя, шапки и
  паспорта конкурируют за одно место; открытие любой закрывает текущую с
  отбросом несохранённых правок (расширение механизма
  `constructions-editor-inline-layers`).
- **Черновик по коммитам шапки/паспорта**: при заданном `draftAction`
  «Сохранить»/«Применить» с изменёнными полями шлют черновик с прежним
  payload'ом; без изменений и на ввод внутри формы — не шлют.
- Схемы props не меняются вовсе; python-зеркало и фикстуры не трогаются.
  Вкладка общих данных — вне скоупа (отдельный change при необходимости).

## Capabilities

### New Capabilities

- `constructions-editor-header-edit`: жизненный цикл шапки карточки и
  паспортного Rпр — режим чтения ↔ форма редактирования, коммиты
  «Сохранить»/«Применить», участие в правиле «одна форма на весь редактор».

### Modified Capabilities

- `constructions-editor`: требование «Редактирование целиком на клиенте» —
  правки типа/subtype/названия и `rprPassport` попадают в state только по
  коммиту соответствующей формы (раньше — сразу, на каждый ввод).
- `constructions-editor-draft`: триггеры автосохранения — к коммитам формы
  слоя добавляются коммиты формы шапки и формы паспортного Rпр;
  формулировка «правки полей не запускают автосейв» сужается до ввода внутри
  ещё не закоммиченных форм и полей вкладки общих данных.

## Impact

- `catalog-react`: `constructions-editor-card.tsx` (режимы шапки и паспорта,
  их формы), `constructions-editor.tsx` (обобщение state единственной формы:
  слой | шапка | паспорт), `constructions-editor.types.ts`. Логика слоёв и
  lookup'ов не меняется.
- `catalog-schemas`, `catalog-python`: без изменений (props те же).
- Демо `apps/demo`: витрина руками; комментарий логгера актуален
  («по коммитам»).
- Потребители: `spai-ui` — без изменений; `spai-teplo-calc` — хендлер
  `draftAction` не меняется, станет чаще получать черновики.
- **Non-goals**: вкладка общих данных; debounce; блокировка submit;
  изменения схем props.
