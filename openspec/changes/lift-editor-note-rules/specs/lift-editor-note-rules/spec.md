## ADDED Requirements

### Requirement: Строка правила может ставить подпись под полем

Схема `LiftEditor`/`LiftEditorNext` SHALL принимать в строке `dependentRules[].rows[]`
опциональный `note` с полями `field`, `text` (1–160 символов) и опциональным
`tone` (`muted` | `warning`). `set` SHALL быть опциональным. Строка без `set` и
без `note` MUST отвергаться схемой. Прежние props MUST оставаться валидными.

#### Scenario: Строка только с подписью валидна

- **WHEN** правило с источниками `N` (здание) и `Vn` (лифт) содержит строку `{when: [18, '1'], note: {...}}`
- **THEN** валидация схемы проходит

#### Scenario: Пустая строка отвергается

- **WHEN** строка правила не содержит ни `set`, ни `note`
- **THEN** валидация схемы завершается ошибкой

### Requirement: Подпись правила следует текущим значениям и сильнее источника

Компонент SHALL показывать под полем лифта `note.text` совпавшей строки правила,
сравнивая `when` с текущими значениями источников (числа — численно). Подпись
правила MUST заменять пометку источника и `hint` этого поля. Когда совпадения
нет, под полем MUST показываться прежняя подпись (источник, иначе `hint`).

#### Scenario: Смена этажности включает предупреждение

- **WHEN** у лифта Vн = 1 из текста запроса («из вопроса»), пользователь вводит N = 18, а правило содержит строку `[18, 1]`
- **THEN** под Vн этого лифта показан `note.text` тоном предупреждения, пометки источника нет

#### Scenario: Подъём скорости убирает предупреждение

- **WHEN** при N = 18 пользователь меняет Vн лифта на 1,6
- **THEN** подписи правила под Vн нет
