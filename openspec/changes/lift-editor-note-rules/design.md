# Design: lift-editor-note-rules

## Решение 1. Расширить строку правила, а не заводить второй механизм

Подпись — ещё один выход той же таблицы «значения источников → результат».
Совпадение, числовое сравнение (`liftValuesMatch`: '1' = 1 = '1,0'),
кросс-секционные источники (`scope: 'building'`) уже есть у `dependentRules`.
Отдельный проп `noteRules` дублировал бы сопоставление. Цена: `set` стал
опциональным, поэтому `collectRuleTargets` и `applyDependentRules` читают
`row.set ?? {}`. Чьё решение: план #396, срез B.

## Решение 2. Подпись правила сильнее источника (решение пользователя 2026-09-23)

Строка под полем одна. Нормативное предупреждение важнее, чем «из вопроса»:
в репро значение Vн пришло именно из текста, и источник прятал бы
предупреждение. Приоритет: `note` → `source` → `hint`, в обоих рендерерах.

## Решение 3. Подпись считается из текущих значений, а не из присланных

`collectRuleNotes` берёт значения секции после подстановок, поэтому подпись
следует и за ручным вводом, и за «Применить», и за сменой N в «Здании».
Правки поля пометку не «снимают» (в отличие от источника) — подпись зависит
только от значений.

## Решение 4. Первое совпадение, первое правило

Внутри правила — первая совпавшая строка (как у `set`). На одно поле —
первое правило с подписью. Предсказуемо и достаточно для одной таблицы СП 54.

## Решение 5. Только секции лифта

Цели `set` — поля лифта; `note` следует тому же. Подписи полей «Здания» не
заводим: запроса нет.

## Тон

`warning` по умолчанию (`a2ui-t--warning` в наборе, `a2ui-le-caption--warning`
в прежнем рендерере), `muted` — для пояснений. Next-рендерер вешает
`role="status"` на предупреждение, чтобы скринридер его объявил.

## Открытые вопросы

Нет. Бейдж свёрнутой секции («просмотреть») по решению пользователя не меняется.
