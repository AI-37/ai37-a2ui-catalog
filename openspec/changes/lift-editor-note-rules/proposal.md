# LiftEditor: подпись под полем от правила зависимостей

## Why

План [`fix-lift-min-speed-sp54-warning`](https://github.com/AI-37/docs/pull/396), срез B.
СП 54.13330 прил. В задаёт минимальную скорость лифта по этажности жилого здания:
до 17 этажей — 1,0 м/с, 18–25 — 1,6 м/с. При N = 18 и Vн = 1,0 форма молчит — в
трёх случаях: ручной ввод Vн, «Применить» у варианта подбора с 1,0 м/с и значение
из текста запроса (под полем стоит только «из вопроса»).

Предупреждение зависит от ДВУХ значений (N — секция «Здание», Vн — секция
лифта), а агент перерисовать подпись по ходу ввода не может: `calc:draft`
намеренно «немой» (ответный снапшот сбросил бы локальное состояние). Поэтому
подпись должна считаться на клиенте из присланных агентом строк — как уже
считаются `h`/`t123` по Vн.

Что есть сегодня под полем (проверено на повтор механизма):

| механизм | зависит от значений | годится |
|---|---|---|
| `field.hint` | нет, статичен | нет |
| `buildingSources`/`liftSources` | нет, происхождение | нет |
| пометка `missing` | только «пусто» | нет |
| `dependentRules` | да, 1–4 источника, кросс-секционно | **да, но умеет только `set`** |

## What Changes

- **`catalog-schemas`**: строка `dependentRules[].rows[]` получает опциональный
  `note: {field, text ≤ 160, tone?: 'muted' | 'warning'}`; `set` становится
  опциональным; строка без `set` и без `note` отвергается (`superRefine`
  пропсов). Изменение аддитивное: все прежние props валидны, `CATALOG_VERSION`
  остаётся `v2`. Python-зеркало — то же.
- **`catalog-react`**: `collectRuleNotes(rules, building, lift)` — подписи
  секции лифта из текущих значений; оба рендерера (`LiftEditor`,
  `LiftEditorNext`) показывают подпись правила под полем с приоритетом
  **note → источник → hint**.
- Версия пакетов `0.36.0 → 0.37.0`.

Не входит: сама таблица СП 54 — её строки эмитит агент (срез C плана), в
каталоге нормативных таблиц нет.
