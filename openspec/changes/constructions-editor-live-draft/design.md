# Design — живой автосейв условий

## Решение 1: дебаунс на trailing edge, структурные правки — вне дебаунса

Правки полей условий — поток keystroke'ов; шлём draft один раз после паузы
ввода (порядок сотен мс, точное значение — константа рендерера, подбирается
на демо). Последний ввод побеждает: новый keystroke сбрасывает таймер и
payload собирается из актуального state в момент отправки, не в момент
правки. Структурные правки списка конструкций остаются мгновенными — они
редкие и уже работают так.

Отвергнуто: слать на blur поля. Blur не случается при вводе со стрелок
числового инпута и при выборе из dropdown'а; дебаунс покрывает оба случая
одним механизмом.

## Решение 2: ГСОП и бейджи — из ответного снапшота, без клиентской формулы

Draft-ответ агента заменяет сообщение тем же `messageId`; компонент получает
новые props (`general.gsop`, `typeConfigs`) и рендерит их. Локальный state
полей ввода остаётся источником правды для ЗНАЧЕНИЙ полей (инвариант
change `constructions-editor-draft-save` держится), но ПРОИЗВОДНЫЕ (ГСОП,
Rнорм в `typeConfigs`) компонент всегда берёт из props. Затирание ввода
исключает серверный приоритет `echo → draft → calcDoc`
(`constructions-editor-props.ts`).

Отвергнуто: дублировать формулу ГСОП на клиенте. Двух калькуляторов не
бывает — расползутся (правило «единственный компетентный валидатор — агент»).

Следствие: между вводом и обновлением ГСОП есть задержка «дебаунс +
раунд-трип» (локально ~1 с). Это осознанная цена; «—» либо прежнее значение
на время ожидания — приемлемо, спиннер не рисуем.

## Решение 3: submit отменяет отложенный draft

Submit шлёт полный `{general, constructions}` сам — отложенный draft после
него не нужен и опасен: ответ draft'а (снапшот черновика) может прийти позже
ответа submit'а и визуально «откатить» форму. Нажатие submit очищает таймер
дебаунса. Ответы уже отправленных draft'ов не отменяем — in-place replace
идемпотентен по `messageId`, а гонка «draft-ответ после submit-ответа»
существовала и до этого change (не наблюдалась из-за редкости, риск не
растёт).

## Решение 4: кнопка и dirty-логика удаляются целиком

`conditionsDirty`, `onSave`, кнопка «Сохранить» и ГСОП-гейт
`showGsop={!climateDirty}` — весь механизм «явного коммита условий» уходит.
Автосейв делает состояние «несохранённых условий» несуществующим классом
состояний — нечего подсвечивать и нечем управлять.
