# Живой автосейв условий — убрать кнопку «Сохранить», ГСОП и бейджи обновляются при вводе

## Why

Вкладка УСЛОВИЯ сейчас копит правки в локальном state и отдаёт их только по
явной кнопке «Сохранить» (появляется при dirty). Это расходится с макетами
(кнопки там нет) и ломает главный сценарий: ввёл «Москва, tв 20» — ГСОП и
Rнорм-бейджи не обновились, пока не догадаешься нажать «Сохранить». Хуже
того, ГСОП при dirty вообще прячется (`showGsop={!climateDirty}`), то есть
форма наказывает за ввод.

Вся механика для живого поведения уже обкатана (change
`constructions-editor-draft-save` + `constructions-draft-persist` на стороне
teplo-агента): `draftAction` — детерминированный in-place ход без
LLM/биллинга, ответный снапшот несёт пересчитанные `general.gsop` и
`typeConfigs`, серверный приоритет `echo → draft → calcDoc` защищает ввод от
затирания. Не хватает только триггера: правки полей условий автосейв не
запускают.

Проверено E2E 2026-08-14 на локальном стенде: draft-ход с `{general,
constructions}` доезжает до конверта в истории chat-backend и
восстанавливается при повторном открытии треда. «Пропажа» данных после
перезагрузки — отдельный баг spai-ui (первый reload пересоздаёт тред),
change `reload-keeps-thread` в репо spai-ui.

## What Changes

- **Рендерер** `constructions-editor.tsx` / `constructions-editor-conditions.tsx`:
  - изменение любого поля вкладки УСЛОВИЯ (город, назначение, tв, условия
    эксплуатации, tот, zот, tн) запускает `draftAction` с **дебаунсом**:
    серия правок схлопывается в один action после паузы ввода;
  - кнопка «Сохранить» и состояние `conditionsDirty` удаляются;
  - ГСОП виден всегда (`showGsop`-гейт удаляется): рендерится значение
    `general.gsop` из последнего пришедшего снапшота, нет значения — «—»;
  - submit отменяет отложенный (ещё не отправленный) draft — гонка
    «draft после submit» исключается.
- Триггеры структурных правок (добавление/удаление конструкции, коммит
  формы слоя/шапки) не меняются — шлют draft сразу, без дебаунса.
- Схема `constructions-editor.ts` **не меняется**: `draftAction` уже есть,
  payload прежний (`{general, constructions}`).

## Capabilities

### Modified Capabilities

- `constructions-editor-draft`: правки полей условий становятся триггером
  автосейва (с дебаунсом); правки полей конструкций — по-прежнему нет.
  Добавляются требования: отсутствие кнопки сохранения, всегда видимый ГСОП
  из снапшота, отмена отложенного draft при submit.

## Impact

- `catalog-react`: `src/renderers/constructions-editor.tsx`,
  `constructions-editor-conditions.tsx` — дебаунс-триггер, удаление кнопки и
  dirty-логики, снятие ГСОП-гейта. Тесты рендерера — вслед.
- `catalog-schemas`, `catalog-python`: без изменений (контракт прежний).
- Версия: minor bump + CHANGELOG.
- Потребители: `spai-teplo-calc` — без изменений (handleConstructionsDraft
  уже принимает пару `{general, constructions}` и пересчитывает снапшот);
  `spai-chat-backend` — без изменений (in-place draft + durable-персист уже
  работают); `spai-ui` — без изменений.
- Нагрузка: draft — детерминированный ход без LLM/биллинга; дебаунс держит
  частоту на уровне «один action на паузу ввода».
- **Non-goals**: клиентский расчёт ГСОП (сервер остаётся единственным
  калькулятором — Решение 3 design constructions-editor); автосейв на каждый
  keystroke полей конструкций; починка reload-пересоздания треда (spai-ui,
  change `reload-keeps-thread`); REST-канал записи черновика.
