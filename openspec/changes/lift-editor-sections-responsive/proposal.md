# LiftEditor: один экран из сворачиваемых секций, методика в шапке, адаптив

## Why

Макеты SP-AI для подбора лифтов (форма «Параметры расчёта» в чате) расходятся
с текущим `LiftEditor` ровно там же, где расходился `ConstructionsEditor` до
серии `constructions-editor-conditions-responsive` / `-live-draft` /
`pending-nav-single-open`:

1. **Вкладки прячут документ.** «Здание» и «Лифт 1…N» — табы: пользователь не
   видит, что уже заполнено на других экранах, пока не переключится. В макете
   всё — один экран: секция «Здание» сверху, ниже секции лифтов; заполненная
   секция сворачивается в строку-сводку («17 этажей · 63 жильца») с
   «Показать» — тот же паттерн, что блок «Условия расчёта» теплотеха.
2. **Методика — поле в теле формы.** Сейчас `methodField` — первое поле экрана
   «Здание». В макете выбор методики живёт в шапке карточки: справа от
   заголовка «Параметры расчёта» стоит текст «ГОСТ Р 52941-2008 · жилое
   здание», он же — переключатель. Тип здания для 34758 остаётся полем секции
   «Здание» и подставляется в текст шапки.
3. **Дефолты — экспандер без сводки.** Блок «Параметры по умолчанию» (hf, i,
   kp, kt, gammaUp, gammaDown) раскрывается вслепую: в свёрнутом виде не видно
   принятых значений. В макете это строка-сводка со значениями
   («интенсивность 8 % · kp 0,7 · kt 1,05 · …») — принятое видно без клика.
4. **Кнопка «Рассчитать» блокируется.** `disabled` при незаполненных
   обязательных полях противоречит принятой в `ConstructionsEditor` доктрине
   и ничего не подсказывает. В макете кнопка двухрежимная: пока документ не
   собран — «Далее» (сворачивает текущую секцию, раскрывает следующую
   незаполненную), когда собран — «Рассчитать».
5. **Автосейв только по границам экранов и blur.** У теплотеха черновик
   уходит debounce'ом на любую правку (`constructions-editor-live-draft`);
   лифтовый редактор при тех же ставках (документ собирается минутами)
   сохраняет реже.
6. **Стили инлайновые.** Нет адаптива: `FIELD_COLUMN_WIDTH = 420` держит одну
   колонку в широком чате, а на узком контейнере двухколоночная сетка макета
   невозможна — в inline-CSS не бывает container queries. Механизм уже
   построен для `ConstructionsEditor` (инжектируемый CSS-слой + `@container`),
   `LiftEditor` на него не переведён.
7. **У полей нет источников.** В макете под полями подписи «из вашего
   вопроса», «предложено по классу здания» — provenance, уже смоделированный
   в `generalSources` теплотеха; в `LiftEditor` канала нет.

## What Changes

### Секции вместо вкладок

- **BREAKING (визуально)**: табы удаляются. «Здание» — секция сверху, ниже —
  секции «Лифт 1…N» (`liftsMode: 'per-lift'`) или «Лифтовая группа»
  (`'group'`), затем «+ Добавить лифт» (в per-lift). `buildingTabLabel` и
  `liftTabLabel` из подписей вкладок становятся заголовками секций.
- Каждая секция — два состояния: **свёрнута** (шеврон, заголовок,
  строка-сводка из живых значений, «Показать») и **раскрыта** (сетка полей +
  «Свернуть», у лифта — «Удалить лифт»). Переключение локальное, без
  `dispatchAction`; введённое переживает сворачивание.
- Сводка собирается компонентом из текущих значений (не приходит строкой от
  агента — разъедется после первой правки). Для подписи в сводке у поля
  появляется опциональный `shortLabel` (иначе берётся `name`).
- Начальное состояние: раскрыта первая секция с незаполненными обязательными
  полями, остальные свёрнуты; если незаполненных нет — свёрнуто всё.

### Методика расчёта в шапке

- Новые пропы `headerTitle` / `headerContext` (как у `ConstructionsEditor`) —
  заголовок карточки и текст-контекст от агента (например, имя проекта).
- Правее контекста — **переключатель методики**: текст
  «`gostLabel` · `<тип здания>`», раскрывающийся в выбор из
  `methodConfigs[].label`. Тип здания — значение поля `buildingType` активной
  ветки (34758) либо новый опциональный `methodConfigs[].buildingKindLabel`
  («жилое здание» для 52941). Смена методики и смена типа здания обновляют
  текст шапки локально.
- `methodField` перестаёт рендериться полем секции «Здание» (проп остаётся в
  схеме — подпись и обязательность переключателя).

### Свёрнутые «Параметры по умолчанию» со сводкой

- Блок `advanced`-полей рисуется тем же баннер-паттерном, что секции: строка
  с подписью из `advancedLabel` и сводкой принятых значений + «Показать».
  Правила прежние: обязательное пустое поле в блок не прячется, блок не
  создаётся ради одного-двух полей.

### Двухрежимная кнопка «Далее» / «Рассчитать»

- Новый проп `pendingLabel` (например, «Далее»). Секция считается
  **просмотренной с момента раскрытия** (любым способом); свёрнутые
  непросмотренные помечаются бейджем «просмотреть», незаполненные —
  «заполните». Пока есть незаполненные обязательные поля **или
  непросмотренные секции**, единственная кнопка подвала показывает
  `pendingLabel` и **навигирует вместо отправки**: сворачивает раскрытые
  секции и раскрывает ровно одну следующую (сначала незаполненную, иначе
  непросмотренную по порядку — паттерн `pending-nav-single-open`), скроллит к
  ней. Даже полностью предзаполненный агентом документ проходится по секциям
  до submit'а.
- Когда непройденных секций и незаполненных обязательных полей нет, та же
  кнопка показывает `submitLabel` и отправляет submit. Блокировка `disabled`
  удаляется; пометки незаполненных секций остаются индикацией.

### Live-автосейв

- Триггеры черновика меняются по образцу `constructions-editor-live-draft`:
  любая правка поля — **debounce 500 мс** (константа экспортируется из
  пакета); структурные действия (добавление/удаление лифта, смена методики,
  навигация «Далее») — немедленно, с отменой отложенного. Триггеры «смена
  вкладки» и «blur изменённого поля» отмирают вместе с вкладками.
- Дедупликация по содержимому, равенство payload'а submit'у и поведение без
  `draftAction` — без изменений.

### Provenance полей

- Новые пропы `buildingSources` (объект по именам полей здания) и
  `liftSources` (массив таких объектов по индексам лифтов):
  `{source: 'project' | 'question' | 'suggested' | 'default', note?}` — как
  `generalSources` теплотеха.
- Поведение как у теплотеха, но provenance — только подпись под контролом
  («из проекта», «из вопроса», «предложено агентом», «принято по умолчанию»
  или `note`); оформление самих контролов от источника не меняется. Правка
  поля снимает подпись, в payload provenance не уходит, ничего не блокирует.

### Адаптив по ширине контейнера

- Рендереры `LiftEditor` переезжают с инлайновых стилей на классы
  `a2ui-le-*` + инжектируемый `<style>` (общие `style-tag.tsx` /
  `hash-css.ts`); корень получает `container-type: inline-size`, сетки полей
  — две колонки от ~560px по контейнеру, одна — ниже. `FIELD_COLUMN_WIDTH`
  перестаёт применяться в `LiftEditor`.

## Capabilities

### New Capabilities

- `lift-editor-sections`: контракт одного экрана — секции здания и лифтов со
  сводками, начальное состояние, шапка с переключателем методики, сводка
  блока дефолтов, двухрежимная кнопка «Далее»/«Рассчитать».
- `lift-editor-field-provenance`: контракт `buildingSources`/`liftSources` —
  источники значений, подписи, снятие при правке, невмешательство в submit.
- `lift-editor-responsive-layout`: требования к адаптиву — CSS-слой,
  контейнерные брейкпоинты, отказ от фиксированной колонки.

### Modified Capabilities

- `lift-editor`: дельта `specs/lift-editor/spec.md` модифицирует требования
  pending-спек `lift-editor` и `lift-editor-draft-save` (валидация и
  блокировка submit, триггеры черновика). Требования вкладок, вытесняемые
  секциями, перечислены разделом «Вытесняет» в спеке `lift-editor-sections`.

## Impact

- `catalog-schemas`: `src/components/lift-editor.ts` — `headerTitle`,
  `headerContext`, `pendingLabel`, `buildingSources`, `liftSources`,
  `methodConfigs[].buildingKindLabel`, `field.shortLabel`; всё опционально,
  `CATALOG_VERSION` v2 сохраняется; публикация `pnpm run export:public`.
- `catalog-react`: `renderers/lift-editor.tsx` — секции вместо вкладок,
  шапка, двухрежимная кнопка, live-draft; `lift-editor-tabs.tsx` удаляется;
  новые подфайлы секции/баннера/сводки/подписи источника; новый
  `lift-editor-styles.ts` (CSS-слой, container queries) вместо инлайновых
  стилей; `lift-editor-advanced.tsx` — баннер со сводкой значений.
- `catalog-python`: зеркала новых полей + parity-тест.
- Фикстуры `fixtures/valid|invalid|messages` и превью `apps/demo`
  обновляются под новые пропы (обе методики, provenance, свёрнутые секции).
- Версия: minor bump (`pnpm run version:bump`) + CHANGELOG.
- Потребители: `spai-elevator-calc-agent` — связанный change: билдер props
  (`form-args.ts` / `lift-editor-configs.ts`) отдаёт `headerTitle`,
  `headerContext` (проект), `buildingKindLabel`, `pendingLabel`, источники
  полей из накопленного состояния парсера; имена и payload действий
  `calc` / `calc:draft` не меняются. Без новых пропов компонент рисует то же,
  что сейчас, без шапки и подписей.
- **Non-goals**: изменение payload'а submit/draft; компонент результата
  расчёта; нормативные таблицы ГОСТ на клиенте; персист в localStorage;
  ссылка «изменить только для расчёта» и флаг `readonly`; единицы измерения
  в сводках; адаптив остальных рендереров каталога (FormCard, ChoiceCard).
