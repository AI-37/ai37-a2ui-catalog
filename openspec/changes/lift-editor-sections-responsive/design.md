# Design: LiftEditor — секции, шапка, адаптив, live-draft

## Context

`LiftEditor` (change'ы `lift-editor`, `lift-editor-draft-save`) построен на
поколении FormCard: вкладки, инлайновые стили, блокирующий submit, автосейв по
границам экранов и blur. `ConstructionsEditor` за серию change'ов
(`constructions-editor-conditions-responsive`, `-live-draft`,
`pending-nav-single-open`, `instant-rpr-recalc`) выработал целевые паттерны:
сворачиваемый блок со строкой-сводкой, CSS-слой с container queries,
provenance, debounced-черновик, двухрежимную кнопку. Макеты SP-AI для лифтов
нарисованы в этих же паттернах. Этот change переводит `LiftEditor` на них,
не меняя протокол действий (`submitAction`/`draftAction`, payload
`{method, building, lifts}`).

## Goals / Non-Goals

**Goals**

- Один экран: секции «Здание» и лифтов со сводками, паттерн баннера теплотеха.
- Выбор методики в шапке карточки; текст «ГОСТ · тип здания» как переключатель.
- Сводка значений в свёрнутом блоке «Параметры по умолчанию».
- Двухрежимная кнопка «Далее»/«Рассчитать» вместо `disabled`.
- Live-draft debounce'ом; структурные триггеры — немедленно.
- Provenance полей здания и лифтов.
- Адаптив по контейнеру, отказ от инлайновых стилей.

**Non-Goals**

- Изменение состава полей методик и `dependentRules` (приходят от агента).
- Изменение payload'а действий — агент не должен заметить редизайн ничем,
  кроме новых опциональных props.
- Общий «фреймворк секций» для всех компонентов каталога — переиспользуем
  только `style-tag.tsx`/`hash-css.ts` и словарь `field-source-label`.

## Decisions

### Решение 1: секции с локальным состоянием, а не вкладки и не аккордеон-эксклюзив

Каждая секция (здание, каждый лифт, лифтовая группа) — баннер-строка
(шеврон · заголовок · сводка · «Показать») ↔ раскрытая сетка полей. Состояние
`openSections: Set<key>` живёт в корне; ручное раскрытие **не** сворачивает
соседей (как аккордеон карточек теплотеха — multi-open вручную), сворачивает
их только навигация «Далее» (паттерн `pending-nav-single-open`). Ключ секции
лифта — индекс в массиве; после удаления сет сдвигается
(`shift-touched-after-remove` уже решает эту задачу для touched — тот же
приём).

Отвергнуто: строгий аккордеон (ровно одна открыта всегда) — мешает сверять
здание с лифтом; сохранение вкладок с добавлением сводок — макет прямо
рисует вертикальный поток, и вкладки не показывают N лифтов сразу.

### Решение 2: методика — select в шапке, текст собирается на клиенте

Шапка: слева `headerTitle`, справа `headerContext` (статический текст агента,
например «Проект «ЖК Северный, к.3»»), затем переключатель методики. Его
свёрнутый вид — текст `«{gostLabel} · {тип}»`, где `тип` — живое значение
поля `buildingType` активной ветки, а при его отсутствии —
`methodConfigs[].buildingKindLabel` («жилое здание» для 52941). Раскрытый вид
— нативный select с options из `methodConfigs[].label`. Текст обязан
собираться на клиенте: тип здания правится в секции «Здание», строка от
агента разъехалась бы после первой правки (тот же аргумент, что у сводки
условий теплотеха).

Отвергнуто: `headerContext` с зашитым «ГОСТ …» от агента (протухает при
локальной смене методики); перенос поля `buildingType` в шапку (в 34758 он
управляет `optionsBy`/`dependentRules` и обязан остаться обычным полем
секции — в шапке только его отражение).

### Решение 3: сводки из живых значений, подписи — `shortLabel`

Сводка секции = для каждого не-`advanced` поля с непустым значением:
`{shortLabel ?? name} {value}`, join « · »; сводка блока дефолтов — то же по
`advanced`-полям. Пустые значения опускаются целиком. Единицы измерения в
сводку не вводим (non-goal): подпись вида «Q 1000 · Vн 1,6» достаточна и не
требует нового канала данных.

Отвергнуто: использовать полный `label` («N — число заселённых этажей») —
сводка не влезает в строку; шаблон сводки от агента строкой — протухает.

### Решение 4: двухрежимная кнопка вместо `disabled`

Прямой перенос `pendingLabel`-механики теплотеха (`handlePendingClick`):
при незаполненных обязательных полях кнопка показывает `pendingLabel`, клик
сворачивает текущую секцию и раскрывает ровно первую секцию с незаполненными
обязательными полями + скролл; иначе — `submitLabel` и dispatch. Это
сохраняет инвариант «submit недостижим, пока обязательные пусты» (требование
pending-спеки `lift-editor`), но убирает мёртвую `disabled`-кнопку и даёт
«Далее» из макета бесплатно: заполнил здание → «Далее» сворачивает здание и
раскрывает «Лифт 1».

Отвергнуто: отдельная кнопка «Далее» в каждой секции (две кнопки в подвале
конфликтуют за роль primary; у теплотеха этот путь уже отвергнут).

### Решение 5: CSS-слой как у ConstructionsEditor, префикс `a2ui-le-`

Стили — константа `lift-editor-styles.ts`, инжектируемая общим
`style-tag.tsx` (React 19 `<style href precedence>`, hash по FNV-1a). Корень:
`container-type: inline-size; container-name: a2ui-le; width: 100%;
min-width: 0` (грабли flex-хоста задокументированы в стилях теплотеха).
База — одна колонка; `@container a2ui-le (min-width: 560px)` включает
`grid-template-columns: 1fr 1fr` для сеток полей. Токены — только
`var(--a2ui-*)`; группа `--a2ui-color-le-*` наследует общие токены каталога.
Брейкпоинт один и совпадает с теплотехом (560) — компоненты живут в одной
чат-колонке.

Отвергнуто: расшарить CSS-константу теплотеха (связывает независимые
компоненты: правка стилей одного молча меняет другой); CSS-файл в пакете
(требует бандлер-импорт у потребителя, ломает `sideEffects: false`).

### Решение 6: live-draft — debounce 500 мс + немедленные структурные триггеры

Правка любого поля планирует черновик через
`LIFT_DRAFT_DEBOUNCE_MS = 500` (экспортируется из пакета — тесты и хосты
мотают таймеры тем же числом; значение равно теплотеховскому). Payload
читается из ref в момент срабатывания таймера. Структурные действия
(add/remove лифта, смена методики, навигация «Далее») шлют немедленно и
отменяют отложенный; submit отменяет отложенный черновик. Дедупликация по
сериализованному payload'у (`lastDraft` ref) сохраняется. Blur-триггер и
триггер «смена вкладки» удаляются: debounce строго покрывает blur (правка
уже запланировала отправку), вкладок больше нет.

Отвергнуто: сохранить blur параллельно с debounce (двойные отправки того же
состояния, дедуп гасит, но кода больше, чем пользы).

### Решение 7: provenance — параллельные блоки, снятие по факту правки

`buildingSources: Record<name, {source, note?}>` и
`liftSources: Array<Record<name, {source, note?}>>` (по индексам лифтов) —
зеркало `generalSources`: значения и источники не смешиваются, payload
submit'а не меняется. Подписи — `note`, иначе словоформа из общего словаря
(«из проекта» / «из вопроса» / «предложено агентом» / «принято по
умолчанию»); словарь словоформ выносится из `constructions-editor-*` в
shared-хелпер пакета. Правка поля добавляет ключ в `touched` и снимает
provenance независимо от вернувшегося значения; новый снапшот props
сбрасывает `touched` (механика reseed у `LiftEditor` уже есть). Оформление
контролов от источника не меняется вовсе: акцентную рамку `suggested`-полей
теплотех уже отверг (подсвеченные поля читаются как ошибка), а приглушение
`project`-полей отвергнуто на прототипе — «серое против белого» читается как
disabled и ломает однородность ряда. Provenance — только подпись.

Отвергнуто: `{value, source}` вместо значения поля (меняет payload —
запрещено non-goal'ом); provenance на уровне секции (макет подписывает
каждое поле).

### Решение 8: сводка секции «Здание» не включает методику

Методика видна в шапке всегда; дублировать «ГОСТ …» в сводке секции — шум.
Сводка здания начинается с содержательных полей (для 52941 — N и A, для
34758 — тип, A, N1, Nl).
