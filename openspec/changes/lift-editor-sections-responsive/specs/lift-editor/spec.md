## MODIFIED Requirements

### Requirement: Валидация обязательных полей на клиенте

Компонент SHALL помечать секции, содержащие незаполненные поля с
`required: true`. При заданном `pendingLabel` недостижимость submit'а SHALL
обеспечиваться двухрежимной кнопкой (см. `lift-editor-sections`), а не
`disabled`; без `pendingLabel` кнопка submit SHALL блокироваться, как прежде.
Проверка нормативных диапазонов значений MUST оставаться вне компонента.

#### Scenario: Незаполненная секция помечена

- **WHEN** в секции лифта не заполнено обязательное поле
- **THEN** секция помечена (в том числе в свёрнутом виде), а кнопка подвала
  показывает `pendingLabel` и не отправляет действий

#### Scenario: Заполнение открывает submit

- **WHEN** пользователь заполнил последнее незаполненное обязательное поле
- **THEN** пометки секций снимаются и кнопка подвала показывает `submitLabel`

#### Scenario: Значение вне нормативного ряда не блокирует submit

- **WHEN** заполнены все обязательные поля, но значение `combo`-поля выходит
  за нормативный ряд
- **THEN** submit доступен, а проверка норматива остаётся за агентом

### Requirement: Черновик уходит на границах экранов

При заданном `draftAction` компонент SHALL отправлять черновик немедленно при
структурных действиях: добавлении лифта, удалении лифта, смене методики
расчёта и навигации кнопкой `pendingLabel`. Немедленная отправка SHALL
отменять запланированный debounce-черновик. Триггер смены вкладки SHALL
исчезнуть вместе с вкладками.

#### Scenario: Изменение состава лифтов сохраняется

- **WHEN** пользователь добавляет или удаляет лифт
- **THEN** немедленно отправляется action с именем из `draftAction`, а массив
  лифтов в его контексте соответствует новому составу

#### Scenario: Смена методики сохраняет ставшую активной ветку

- **WHEN** пользователь меняет методику в шапке
- **THEN** отправляется action с именем из `draftAction`, а `method` и
  значения в его контексте принадлежат вновь выбранной методике

#### Scenario: «Далее» фиксирует заполненную секцию

- **WHEN** пользователь заполнил секцию здания и нажал кнопку `pendingLabel`
- **THEN** черновик с введёнными значениями отправляется немедленно, не
  дожидаясь debounce

### Requirement: Черновик уходит при потере фокуса изменённым полем

Требование заменяется live-черновиком: компонент SHALL отправлять черновик
через фиксированную задержку (экспортируемая константа, 500 мс) после
последней правки любого поля активной ветки. Payload SHALL читаться в момент
срабатывания таймера. Потеря фокуса сама по себе SHALL NOT быть триггером;
проход по полям без правок MUST NOT порождать отправок. Отправка submit'а
SHALL отменять запланированный черновик.

#### Scenario: Правка сохраняется без ухода с поля

- **WHEN** пользователь изменил значение поля и не трогает форму дольше
  задержки
- **THEN** отправляется один action с именем из `draftAction`, несущий новое
  значение

#### Scenario: Серия правок схлопывается

- **WHEN** пользователь несколько раз правит поля с паузами меньше задержки
- **THEN** уходит один черновик с последним состоянием

#### Scenario: Submit гасит отложенный черновик

- **WHEN** пользователь правит поле и сразу нажимает «Рассчитать»
- **THEN** уходит только submit; отложенный черновик не отправляется
