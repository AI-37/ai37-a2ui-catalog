## Context

`ConstructionsEditor` рендерит каждый слой раскрытой конструкции сразу формой
(`constructions-editor-layer-row.tsx`): lookup материала, толщина, λ. Правки
уходят наверх на каждое нажатие клавиши (`onChange` целым слоем →
`handleEntryChange` редактора). Следствия:

- Раскрытая конструкция из 4–5 слоёв — стена инпутов; состав не читается,
  сравнить слои глазами нельзя (см. скриншоты в обсуждении change'а).
- Черновик (`constructions-editor-draft-save`) шлётся только на структурные
  правки, отличённые по длине `layers`. Правка поля — прежде всего «добавить
  λ распознанному слою» — черновика не порождает: сценарий «распознали
  конструкции → вписал λ → пере-рендер формы агентом» теряет ввод.
- Ошибка данных в свернутой конструкции (слой без λ) не видна вовсе; в
  текстовом выводе агента такие конструкции помечены «(! проверить)», у формы
  эквивалента нет.

Обсуждались и отвергнуты: debounce на любую правку поля (вариант 2 из
обсуждения) — стал не нужен, как только у формы слоя появился явный коммит;
флаг «изменено» на карточке — заменён производной подсветкой невалидности.

## Goals / Non-Goals

**Goals:**

- Состав конструкции читается: слой — одна строка-сводка, форма — только у
  редактируемого.
- Правки полей слоя доезжают до агента без submit'а: коммит формы — точка
  отправки черновика.
- Ошибка данных видна на карточке (и свернутой) цветом, из данных, без
  участия агента.
- Схема props не меняется; payload черновика и submit'а прежние.

**Non-Goals:**

- Debounce и черновик на правки полей шапки конструкции
  (тип/subtype/название/`rprPassport`) и вкладки общих данных.
- Клиентская блокировка submit'а: подсветка невалидности — индикация,
  submit по-прежнему уходит как есть (о недостающем сообщает агент).
- Изменения схем (`catalog-schemas`, `catalog-python`), фикстур валидации.
- Черновик «на закрытие формы без Применить», persist несохранённых правок
  формы.

## Decisions

### Решение 1. Два режима строки слоя, раскрыта максимум одна форма

`ConstructionsEditorLayerRow` получает режим: `summary` (строка: номер,
материал, толщина, λ со значком «авто» / ручное значение / предупреждение
«λ не задана»; вся строка кликабельна) и `edit` (сегодняшняя форма + кнопки).
Каким слоем владеет форма, знает редактор: `editingLayer: {entryId, index} |
null` в state `ConstructionsEditor`, карточка получает свой `editingIndex`
пропом. Состояние именно в редакторе, а не в карточке: требование «раскрыта
максимум одна форма на весь редактор» при per-карточном state нарушалось бы
двумя раскрытыми карточками. Клик по другой строке (в том числе другой
карточки) переводит форму туда, несохранённые правки прежней формы
отбрасываются (см. Решение 2).

Альтернатива — аккордеон «раскрыто много форм» с per-строчным флагом:
возвращает простыню, ради которой всё затевалось, и умножает состояния.

### Решение 2. Форма владеет черновиком слоя, коммит — «Применить»

В режиме `edit` строка держит локальную копию слоя (`useState` от
`layer` при открытии). Ввод меняет только копию: state редактора, live-Rпр
и черновики не трогаются. «Применить» отдаёт копию наверх (`onChange`) —
это единственный момент, когда правка полей слоя попадает в state; «Отмена» и
клик по другой строке отбрасывают копию.

Альтернатива — оставить сквозной `onChange` на каждое нажатие и считать
«Применить» только сигналом для черновика. Проще диффать, но тогда «Отмена»
невозможна (правки уже в state), а live-Rпр прыгает во время набора. Явный
коммит даёт согласованную семантику: что видно в строках-сводках — то и есть
state.

Плата: правки, не закрытые «Применить», теряются молча. Осознанно — форма
одна, объём потери — одна строка.

### Решение 3. «+ Слой» открывает форму, слой появляется по «Добавить»

`handleLayerAdd` больше не вставляет `{material: '', thicknessMm: null}` в
state. Вместо этого карточка открывает форму нового слоя
(`editingIndex: 'new'`), кнопка коммита — «Добавить», «Отмена» не оставляет
следа. Так в state (и в черновиках, и в submit'е) не копятся пустые строки от
случайных нажатий.

### Решение 4. Черновик — по коммитам, сравнение длин `layers` уходит

Триггеры `draftAction`: «Применить» (если копия отличается от исходного
слоя), «Добавить», «Удалить слой», add/remove конструкции. Все триггеры
становятся явными событиями (карточка сообщает редактору «был коммит»), хак
с `current.layers.length !== next.layers.length` в `handleEntryChange`
удаляется. Payload прежний — полный `{general?, constructions}`, как у
submit'а; ответ агента по-прежнему не читается.

Для `spai-teplo-calc` контракт не меняется (тот же action, тот же payload),
меняется только частота: плюс один-два action'а на отредактированный слой.
Хендлер детерминированный, без LLM — приемлемо.

### Решение 5. Невалидность — производное состояние, без схемы и без событий

Слой невалиден, если он `kind: 'material'` (или без `kind`) и у него нет λ
(ни `lambdaA`/`lambdaB`, ни `lambdaManual`), нет положительной `thicknessMm`
или пуст `material`. Конструкция невалидна, если невалиден хоть один слой
(для типов без слоёв — нет `rprPassport`). Считается чистой функцией от
`ConstructionEntry` рядом с `computeLiveRpr` — на каждый рендер, как live-Rпр.

Отображение: у карточки в любом состоянии (свернутой и раскрытой) — цветовая
подсветка (полоска/рамка предупреждающим цветом из `tokens`) и короткая
пометка «проверить: …» у заголовка; у невалидной строки-сводки — «λ не
задана» тем же цветом. Гаснет само, когда причина устранена. В схему ничего
не добавляется: агент при желании выводит то же самое текстом, как уже делает
(«(! проверить)»).

Альтернатива — флаг от агента в props: лишний раунд-трип и рассинхрон с
локальными правками, при том что клиент видит те же данные.

## Risks / Trade-offs

- **Потеря несохранённых правок формы при «Отмене»/переключении строки** →
  объём — одна строка; кнопка «Применить» всегда на виду в форме. Если
  окажется больно — подтверждение при переключении отдельным change'ом.
- **Лишний клик на правку** (открыть строку → править → «Применить») против
  сегодняшнего прямого ввода → плата за читаемость списка и за точку
  коммита; типичный сценарий (поправить λ в одном-двух слоях) — два клика
  сверху.
- **Рост числа `draftAction`** → по-прежнему только осознанные, редкие
  действия (коммиты), не ввод символов; хендлер агента детерминированный.
- **Подсветка ≠ валидация submit'а** → пользователь может отправить
  невалидное — как и сегодня на объединённом экране; подсветка лишь делает
  это видимым до отправки.
- **Тесты рендерера, завязанные на «все слои — формы»** → правятся вместе с
  change'ем; сценарии lookup'а материала не меняются (форма та же, просто
  открывается по клику).

## Migration Plan

Только `catalog-react` (+ демо): minor bump, CHANGELOG. Схемы и python-модель
не меняются — потребители обновляют пакет рендереров без координации выката.
`spai-teplo-calc` изменений не требует. Откат — предыдущая версия пакета.
