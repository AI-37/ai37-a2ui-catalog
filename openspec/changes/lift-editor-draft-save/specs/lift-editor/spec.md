## ADDED Requirements

### Requirement: Автосохранение черновика опционально

Схема `LiftEditor` SHALL принимать опциональный проп `draftAction` — имя
action'а автосохранения. Если проп не задан, компонент MUST NOT отправлять
никаких действий, кроме submit'а.

#### Scenario: Без пропа поведение прежнее

- **WHEN** в props нет `draftAction`, а пользователь переключает вкладки,
  добавляет и удаляет лифты, меняет методику и вводит значения
- **THEN** наружу не уходит ни одного `dispatchAction` до нажатия submit'а

#### Scenario: Пустое имя action'а отвергается схемой

- **WHEN** в props передан `draftAction` пустой строкой
- **THEN** валидация схемы завершается ошибкой

### Requirement: Черновик уходит на границах экранов

При заданном `draftAction` компонент SHALL отправлять черновик при смене
активной вкладки, при добавлении лифта, при удалении лифта и при смене
методики расчёта.

#### Scenario: Смена вкладки сохраняет введённое

- **WHEN** пользователь ввёл значения на вкладке лифта и перешёл на вкладку
  здания
- **THEN** отправляется action с именем из `draftAction`, несущий введённое
  значение

#### Scenario: Изменение состава лифтов сохраняется

- **WHEN** пользователь добавляет или удаляет лифт
- **THEN** отправляется action с именем из `draftAction`, а массив лифтов в его
  контексте соответствует новому составу

#### Scenario: Смена методики сохраняет ставшую активной ветку

- **WHEN** пользователь меняет методику расчёта
- **THEN** отправляется action с именем из `draftAction`, а `method` и значения
  в его контексте принадлежат ВНОВЬ выбранной методике

### Requirement: Черновик уходит при потере фокуса изменённым полем

Компонент SHALL отправлять черновик, когда поле активного экрана теряет фокус и
его значение отличается от значения на момент получения фокуса. Потеря фокуса
полем, значение которого не менялось, MUST NOT приводить к отправке.

#### Scenario: Правка поля сохраняется без ухода с экрана

- **WHEN** пользователь изменил значение поля и увёл фокус, оставаясь на той же
  вкладке
- **THEN** отправляется action с именем из `draftAction`, несущий новое значение

#### Scenario: Проход по полям без правок ничего не шлёт

- **WHEN** пользователь получает и теряет фокус на полях, не меняя значений
- **THEN** наружу не уходит ни одного action

### Requirement: Контекст черновика совпадает с контекстом submit'а

Контекст черновика SHALL быть равен `{method, building, lifts}` активной ветки —
тому же, что уходит в submit. Черновики неактивных методик MUST NOT попадать в
контекст.

#### Scenario: Черновик несёт тот же документ, что и submit

- **WHEN** пользователь заполнил здание и лифты, вызвал автосохранение, а затем
  нажал submit, ничего больше не меняя
- **THEN** контексты обоих action'ов совпадают

#### Scenario: Данные неактивной ветки в черновик не попадают

- **WHEN** пользователь заполнял обе методики, а автосохранение сработало при
  активной одной
- **THEN** контекст черновика содержит значения только активной методики

### Requirement: Черновик не блокируется незаполненными полями

Компонент SHALL отправлять черновик независимо от наличия незаполненных
обязательных полей. Блокировка по незаполненным обязательным полям MUST
относиться только к submit'у.

#### Scenario: Неполный документ сохраняется

- **WHEN** на вкладке лифта не заполнено обязательное поле и срабатывает
  триггер автосохранения
- **THEN** черновик отправляется с незаполненным полем как есть, а кнопка
  submit остаётся недоступной

### Requirement: Повторный черновик с тем же содержимым не отправляется

Компонент MUST NOT отправлять черновик, контекст которого совпадает с
контекстом последнего отправленного черновика.

#### Scenario: Два триггера подряд на одно состояние

- **WHEN** пользователь изменил поле, увёл фокус и сразу переключил вкладку
- **THEN** наружу уходит ровно один action автосохранения, а не два

#### Scenario: Переключение вкладок туда-обратно без правок

- **WHEN** пользователь переключает вкладки, ничего не изменив после
  предыдущего автосохранения
- **THEN** новых action'ов автосохранения не отправляется
