## Why

`ConstructionsEditor` держит все правки в локальном state и отдаёт их наружу
единственным submit'ом. Любой раунд-трип до submit'а — прежде всего кнопка
«Общие данные» (`backAction`) — уводит пользователя на другое сообщение, а
введённые конструкции никуда не уехали: агент их не видел и при возврате
рисует форму из пустоты. Воспроизводится руками: добавил конструкцию,
назвал её, нажал «Общие данные», вернулся — пусто.

Канал для починки уже есть и уже обкатан на lookup'е (`form-card-lookup-field`):
action → агент-владелец по `surfaceId` → ответ `ACTIVITY_SNAPSHOT` с тем же
`messageId`, то есть без нового сообщения в чате. Нужен один такой action у
редактора конструкций.

## What Changes

- **Схема** `constructions-editor.ts`: опциональный проп `draftAction?: string`
  (имя action'а автосохранения). Нет пропа — поведение компонента ровно
  сегодняшнее, автосейва нет. Изменение аддитивное, `CATALOG_VERSION` v2
  сохраняется.
- **Рендерер** `constructions-editor.tsx`: на **структурных** правках —
  добавление/удаление конструкции, добавление/удаление слоя — компонент шлёт
  `dispatchAction({name: draftAction, context: {constructions}})` с полным
  текущим массивом. Правки полей (название, толщина, материал, λ) сами по себе
  автосейв не запускают — они уезжают вместе с ближайшим структурным
  действием или submit'ом.
- Ответ агента компонент не читает: state остаётся локальным, перерисовка
  формы тем же `messageId` — забота агента-владельца.
- **Python-зеркало**, фикстуры, тесты, демо — вслед за схемой.

## Capabilities

### New Capabilities

- `constructions-editor-draft`: контракт автосохранения черновика —
  когда компонент шлёт `draftAction`, что кладёт в `context`, и что при этом
  не меняется (локальный state, submit, валидация).

### Modified Capabilities

_(нет — требования `constructions-editor` не меняются: новый проп
опционален, при его отсутствии компонент ведёт себя как раньше)_

## Impact

- `catalog-schemas`: `src/components/constructions-editor.ts` (+1 опциональное
  поле), публикация через `pnpm run export:public`.
- `catalog-react`: `src/renderers/constructions-editor.tsx` — определение
  «структурной» правки и один новый `dispatchAction`. Подфайлы карточки и
  строки слоя не меняются.
- `catalog-python`: `models/constructions_editor.py` + parity-тест.
- Версия: minor bump + CHANGELOG.
- Потребители: `spai-ui` — изменений нет (путь `dispatchAction → a2uiAction →
  агент` уже работает). `spai-teplo-calc` — детерминированный хендлер
  `draftAction`: положить массив в состояние сессии и ответить снапшотом с
  тем же `messageId` (связанный change на стороне агента).
- **Non-goals**: debounce и автосейв на правку полей; отправка состояния
  вместе с `backAction`; объединение «Общих данных» и «Конструкций» в табы;
  персист черновика на клиенте (`localStorage`) и в оркестраторе
  (`RemoteAgentSurface.draft`); чтение ответа агента компонентом.
