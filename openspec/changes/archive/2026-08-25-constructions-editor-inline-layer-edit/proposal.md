## Why

Сейчас все слои каждой раскрытой конструкции отрисованы полными формами
редактирования: десяток конструкций по 3–5 слоёв — простыня инпутов, в которой
не видно состава конструкции и легко промахнуться. При этом правки полей
(в первую очередь λ у распознанного слоя) живут только в локальном state и
уезжают к агенту лишь с submit'ом — сценарий «распознали конструкции → добавил
λ в слое → ушёл/пере-рендер» теряет ввод, потому что правка поля не считается
структурной и `draftAction` не шлётся.

Решение одним изменением UX: слой по умолчанию — компактная строка-сводка,
редактируется ровно один слой раскрытой формой с явной кнопкой «Применить».
Явный коммит даёт естественную точку отправки черновика (без debounce) и
закрывает потерю правок полей слоя. Конструкцию с ошибкой в данных (нет λ,
толщины) компонент подсвечивает цветом — аналог пометки «(! проверить)» из
текстового вывода агента.

## What Changes

- **Строка слоя — компактная сводка**: `№ · материал · толщина · λ` (λ со
  значком «авто» у справочной, значение у ручной, предупреждение «λ не задана»
  у незаполненной). Клик по строке раскрывает форму редактирования; раскрыта
  максимум одна форма на весь редактор.
- **Форма слоя с явным коммитом**: кнопки «Применить» (правки уходят в state
  редактора), «Отмена» (откат к строке без изменений), «Удалить слой».
  До «Применить» правки живут только внутри формы: live-Rпр и state редактора
  не меняются.
- **«+ Слой» открывает пустую форму** (кнопка коммита — «Добавить») вместо
  немедленной вставки пустой строки в state; «Отмена» не оставляет следа.
- **Черновик по коммитам**: при заданном `draftAction` компонент шлёт черновик
  на каждый коммит — «Применить», «Добавить», «Удалить слой» — в дополнение к
  прежним add/remove конструкции. Debounce не вводится; правки полей шапки
  конструкции (тип/subtype/название/`rprPassport`) и вкладки общих данных
  по-прежнему уезжают со следующим коммитом или submit'ом.
- **Подсветка невалидной конструкции**: карточка (и свернутая, и раскрытая),
  у которой в данных ошибка — слой без λ (нет ни справочной, ни ручной), без
  толщины или материала — подсвечивается цветом с короткой пометкой
  «проверить…». Состояние производное, считается на клиенте из данных; ушла
  причина — гаснет подсветка. Схема не меняется.
- Схемы props не меняются вовсе; python-зеркало и фикстуры не трогаются.
  Демо и тесты рендерера — вслед за новым UX.

## Capabilities

### New Capabilities

- `constructions-editor-inline-layers`: жизненный цикл строки слоя —
  компактная сводка ↔ единственная раскрытая форма, коммит «Применить» /
  «Добавить» / «Удалить слой», флоу «+ Слой», производная подсветка
  невалидной конструкции.

### Modified Capabilities

- `constructions-editor`: требование «Редактирование целиком на клиенте» —
  добавление слоя больше не вставляет пустую строку немедленно («+ Слой»
  открывает форму, слой появляется по «Добавить»); правка полей слоя попадает
  в state редактора только по «Применить».
- `constructions-editor-draft`: триггеры автосохранения — к структурным
  правкам добавляются коммиты формы слоя («Применить» с изменёнными полями);
  формулировка «правки полей не запускают автосейв» сужается до полей вне
  формы слоя (шапка конструкции, общие данные) и до ввода внутри ещё не
  закоммиченной формы.

## Impact

- `catalog-react`: `constructions-editor-card.tsx` (список строк, «+ Слой»,
  подсветка невалидности), `constructions-editor-layer-row.tsx` (режимы
  строка/форма, локальный state формы, кнопки коммита),
  `constructions-editor.tsx` (отправка черновика по коммитам вместо сравнения
  длин `layers`), `constructions-editor.types.ts`. Lookup-хук строки слоя
  переиспользуется как есть.
- `catalog-schemas`, `catalog-python`: без изменений (props те же).
- Демо `apps/demo`: логгер черновиков остаётся, комментарий про «структурные
  правки» обновляется.
- Потребители: `spai-ui` — без изменений; `spai-teplo-calc` — хендлер
  `draftAction` не меняется (payload прежний), станет лишь чаще получать
  черновики.
- **Non-goals**: debounce; черновик на правку полей шапки/общих данных;
  клиентская блокировка submit'а по невалидности (подсветка — индикация, не
  блок); изменения схемы props.
