## Why

Экран теплотехнического расчёта сейчас разрезан на два сообщения: «Исходные
данные» (FormCard) и «Конструкции» (`ConstructionsEditor`). Между ними —
раунд-трип: кнопка «← Общие данные» шлёт `backAction`, агент рисует другую
форму, возврат рисует редактор заново. Отсюда потеря ввода (черновик из
`constructions-editor-draft-save` закрывает её лишь на структурных правках),
лишние сообщения в треде и невозможность видеть ГСОП рядом с чипами Rпр.

При этом на момент **ввода** вкладки друг от друга не зависят: исходные данные
и конструкции заполняются в любом порядке, а нормативы считает агент после
submit'а. Значит два экрана можно свести в один компонент с табами, и
раунд-трип исчезает вместе с классом ошибок «данные не доехали».

## What Changes

- **Табы в `ConstructionsEditor`**: «Общие данные» и «Конструкции» —
  переключение локальное, без action'ов. Кнопка `backAction` на объединённом
  экране не нужна: `backLabel`/`backAction` становятся **опциональными**
  (для эмитентов, которые их шлют, поведение прежнее).
- **Новый блок props `general`** — доменные поля климата и здания:
  `buildingType`, `city`, `tot`, `zot`, `tn`, `tv`, `condition`. Значения
  приходят от агента и правятся на клиенте, как конструкции.
- **Lookup города** (`cityReferenceId`, тот же fetch-канал): выбранная опция
  может нести `tot`/`zot`/`tn` — компонент подставляет их в соответствующие
  поля, оставляя редактируемыми. Тот же приём, что λА/λБ в строке слоя;
  контракт `LookupOption & Record<string, unknown>` уже это допускает.
- **Submit больше не блокируется клиентом**: `submitAction` уходит всегда, с
  полным `{general, constructions}` как есть — включая дыры. Чего не хватает,
  агент отвечает текстом. Подсветка обязательных полей и блокировка кнопки
  **удаляются**.
- **Чипы Rнорм — только когда цифра честная**: `typeConfigs[].rnorm` посчитан
  агентом из климата, который был в props. Пользователь тронул любое поле
  климата → сравнение и сводка «проходит N из M» скрываются до следующего
  ответа агента; остаётся «Rпр 3,61» без сравнения.
- **`condition` переезжает в `general`**: одноимённый top-level проп остаётся
  как начальное значение и помечается deprecated; выбор λА/λБ в live-Rпр берёт
  значение из state таба «Общие данные».
- **`draftAction` шлёт `{general, constructions}`** — черновик покрывает обе
  вкладки.

## Capabilities

### New Capabilities

- `constructions-editor-general-tab`: контракт объединённого экрана — табы,
  props блока `general`, lookup города с автозаполнением климата, единый
  submit без клиентской блокировки, правила показа чипов Rнорм.

### Modified Capabilities

_(в `openspec/specs/` спеки не синканы; требования pending-спеки
`constructions-editor`, которые этот change вытесняет — блокирующая
клиентская валидация submit'а и обязательность `backLabel`/`backAction` —
перечислены в спеке новой capability явным разделом «Вытесняет»)_

## Impact

- `catalog-schemas`: `src/components/constructions-editor.ts` — схема
  `general`, `buildingTypeOptions`, `cityReferenceId`, лейблы табов;
  `backLabel`/`backAction` → optional; `condition` → deprecated.
- `catalog-react`: `constructions-editor.tsx` — табы и общий state; новый
  подфайл `constructions-editor-general.tsx` (форма общих данных +
  `LookupCombobox` + `use-lookup-suggest`); удаление блокирующей валидации из
  `handleSubmit`; правило «климат тронут → чипы без сравнения».
  `validate-constructions.ts` остаётся только как источник подсказок? — нет,
  удаляется вместе с блокировкой (см. design.md).
- `catalog-python`: зеркало новых моделей + parity-тест.
- Версия: minor bump + CHANGELOG. Схема аддитивна (новые поля опциональны,
  обязательные — ослабляются), `CATALOG_VERSION` v2 сохраняется.
- Потребители: `spai-teplo-calc` — экран «Общие данные» перестаёт быть
  отдельной FormCard, props собираются одним билдером, submit обрабатывает
  обе половины и отвечает текстом о недостающем (связанный change).
  `spai-ui` — без изменений.
- **Non-goals**: generic-механизм «опция lookup заполняет соседние поля» для
  FormCard; расчёт ГСОП и Rнорм на клиенте (коэффициенты `a`/`b` табл. 3 СП 50
  не переезжают); третий таб; сохранение выбранного таба между ходами.
