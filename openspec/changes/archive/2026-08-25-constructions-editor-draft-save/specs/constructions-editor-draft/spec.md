## ADDED Requirements

### Requirement: Опциональный проп автосохранения

Схема `ConstructionsEditor` SHALL принимать опциональный проп
`draftAction: string` (1–120 символов) — имя action'а автосохранения
черновика. При отсутствии пропа компонент SHALL вести себя как до изменения:
никаких action'ов, кроме `submitAction` и `backAction`.

#### Scenario: Проп отсутствует

- **WHEN** агент прислал props без `draftAction`
- **THEN** props проходят валидацию схемы
- **AND** ни одно редактирование конструкций не порождает `dispatchAction`

#### Scenario: Проп задан

- **WHEN** агент прислал props с `draftAction: "constructions:draft"`
- **THEN** props проходят валидацию схемы

#### Scenario: Пустое имя action'а

- **WHEN** агент прислал `draftAction: ""`
- **THEN** валидация схемы отклоняет props

### Requirement: Автосохранение на структурных правках

При заданном `draftAction` компонент SHALL отправлять
`dispatchAction({event: {name: draftAction, context: {constructions}}})` после
каждой структурной правки — добавления конструкции, удаления конструкции,
добавления слоя, удаления слоя. `constructions` SHALL содержать полный текущий
массив в том же формате, в каком он уходит в `submitAction`, включая
незаполненные и невалидные записи.

#### Scenario: Добавлена конструкция

- **WHEN** пользователь нажимает кнопку добавления конструкции
- **THEN** компонент отправляет один action с именем `draftAction`
- **AND** в `context.constructions` присутствует новая пустая конструкция
  вместе со всеми ранее введёнными

#### Scenario: Удалена конструкция

- **WHEN** пользователь удаляет карточку конструкции
- **THEN** компонент отправляет один action с именем `draftAction`
- **AND** удалённой конструкции нет в `context.constructions`

#### Scenario: Добавлен или удалён слой

- **WHEN** пользователь добавляет либо удаляет строку слоя внутри конструкции
- **THEN** компонент отправляет один action с именем `draftAction`
- **AND** в `context.constructions` эта конструкция содержит актуальный набор
  слоёв

#### Scenario: Незаполненные данные не мешают

- **WHEN** структурная правка происходит при незаполненных обязательных полях
- **THEN** компонент всё равно отправляет `draftAction`
- **AND** клиентская валидация не запускается и подсветка ошибок не
  появляется

### Requirement: Правки полей не запускают автосохранение

Компонент SHALL NOT отправлять `draftAction` в ответ на изменение значений
полей — типа конструкции, subtype, названия, толщины слоя, материала, λ,
паспортного Rпр — а также на разворачивание и сворачивание карточки. Такие
правки SHALL уезжать наружу вместе со следующим `draftAction` либо с
`submitAction`.

#### Scenario: Правка поля без структурного действия

- **WHEN** пользователь меняет название конструкции и толщину слоя
- **THEN** компонент не отправляет ни одного action'а

#### Scenario: Правка поля перед структурным действием

- **WHEN** пользователь меняет название конструкции, а затем добавляет
  вторую конструкцию
- **THEN** отправляется ровно один action `draftAction`
- **AND** в `context.constructions` первая конструкция содержит новое
  название

### Requirement: Автосохранение не меняет состояние компонента

Компонент SHALL сохранять локальный state как единственный источник правды:
отправка `draftAction` не сбрасывает и не перезаписывает рабочую копию
конструкций, не влияет на состояние аккордеона, на клиентскую валидацию и на
live-расчёт Rпр. Ответ агента на `draftAction` компонент SHALL NOT читать.

#### Scenario: State переживает автосохранение

- **WHEN** после отправки `draftAction` пользователь продолжает править поля
- **THEN** введённые значения и открытые карточки остаются на месте

#### Scenario: Submit не меняется

- **WHEN** пользователь нажимает кнопку submit после серии автосохранений
- **THEN** поведение submit'а прежнее: невалидное состояние блокируется
  подсветкой, валидное уходит одним action'ом `submitAction` с полным
  массивом
