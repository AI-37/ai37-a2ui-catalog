# Эхо черновика КЕО — ack, а не новый документ

## Why

Change `keo-editor-draft` (Решение 5) пообещал: «Ответ на черновик не
сбрасывает состояние экрана». Обещание держится на `keoDocumentKey` — сравнении
документа пришедших props с живым состоянием. Ключ — голый `JSON.stringify`
значений, и в проде защита рвётся дважды; наблюдаемый симптом один: секция
«Коэффициенты приняты по умолчанию» схлопывается под руками, фокус вылетает из
поля (воспроизведено headless-браузером на SP-AI, 2026-08-28).

1. **Порядок ключей — не содержание, а ключ на него реагирует.** Снапшот формы
   из истории треда проходит через jsonb Postgres, который пересортировывает
   ключи объекта (длина, затем алфавит). Живое эхо агента несёт порядок
   `KEO_FIELD_MAP`. После перезагрузки страницы состояние посеяно в одном
   порядке, эхо приходит в другом — строки не равны, и ПЕРВАЯ ЖЕ пауза ввода
   пересевает экран: новые id помещений, ремоунт поддерева, сброс раскрытия и
   фокуса.

2. **Эхо сравнивается не с тем.** Guard сверяет эхо с ТЕКУЩИМ состоянием. Но
   эхо по природе отстаёт: пока черновик в полёте, пользователь печатает
   дальше, и состояние уже ушло вперёд. Расхождение принимается за новый
   документ — пересев стирает свежие нажатия. Это не только схлопывание, это
   потеря введённого.

## What Changes

- **`keoDocumentKey` становится каноническим**: ключи условий и значений
  помещения сортируются перед сериализацией; `undefined`-значения
  отбрасываются, как их отбросил бы `JSON.stringify` объекта. Порядок ключей
  перестаёт отличать документы.
- **Своё эхо узнаётся по последнему отправленному черновику.** Хук запоминает
  документный ключ отправленного черновика (`lastDraftKey`, рядом с
  существующим дедупом `lastDraft`) и при смене props считает снапшот ack'ом,
  если его ключ равен ключу последнего черновика ИЛИ ключу живого состояния.
  Ack не пересевает ничего.
- Пересев по настоящему новому сообщению агента (другой документ) — без
  изменений.

## Capabilities

### Modified Capabilities

- `keo-editor-draft` — уточняется требование «Ответ на черновик не сбрасывает
  состояние экрана»: нечувствительность к порядку ключей и ack по последнему
  отправленному черновику.

## Impact

- `packages/catalog-react/src/renderers/keo-document-key.ts` — сортировка
  ключей.
- `packages/catalog-react/src/renderers/use-keo-editor-next.ts` —
  `lastDraftKey` + ветка ack в guard'е пересева.
- `tests/react/keo-editor-next.test.tsx` — два сценария: эхо с другим порядком
  ключей; эхо, отставшее от живого ввода.
- Схемы, Python-зеркало, агенты — не затрагиваются: формат черновика и props
  не меняются.
