## Context

`ConstructionsEditor` сегодня: два таба (`constructions-editor-tabs.tsx`),
вкладка общих данных семью полями в столбик (`constructions-editor-general.tsx`),
карточки конструкций аккордеоном, слои — строки-сводки с одной формой правки на
редактор. Вся раскладка задана инлайновыми `style={{}}`, ширина контента
ограничена константой `FIELD_COLUMN_WIDTH = 420` (`shared.ts:27`). Цвета уже
вынесены в CSS-переменные `--a2ui-*` с fallback'ами (`tokens.ts`).

Сборка пакета — голый `tsc -p tsconfig.json`, без бандлера и без CSS-конвейера.
В `package.json` стоит `"sideEffects": false`. Значит вариант «положить рядом
`styles.css` и импортировать» требует и правки сборки, и действия от каждого
потребителя, и снимает флаг `sideEffects`.

Макеты («Бриф без проекта», «Бриф — слои и подбор», «Бриф — здание из
8 конструкций») требуют трёх вещей сразу: блока условий вместо табов,
provenance-подписей и раскладки на всю ширину со схлопыванием на узком экране.
Первые две — контракт схемы, третья — механизм стилизации; они попали в один
change, потому что двухколоночная сетка условий из макета без адаптива
существовать не может.

## Goals / Non-Goals

**Goals:**

- Один экран: условия (сворачиваемые) + конструкции, без табов.
- Источник каждого значения `general` виден пользователю и объяснён словами.
- Компонент занимает ширину контейнера и корректно сжимается до мобильной
  ширины — по ширине **контейнера**, а не окна.
- Схема остаётся аддитивной: старые эмитенты рисуются без ошибок.

**Non-Goals:**

- Слои редактируемой таблицей, статус-чипы конструкций, блок коэффициентов
  (r, αв, αн), счётчик «N из проекта · M предложены агентом», provenance на
  слоях — отдельные change'ы.
- Компонент результата расчёта.
- Адаптив в `LiftEditor`, `FormCard` и прочих рендерерах: механизм этот change
  вводит, но применяет только к `ConstructionsEditor`.
- Расчёт ГСОП на клиенте.

## Decisions

### Решение 1: Стили — React 19 `<style href precedence>`, не CSS-файл

Раскладка переезжает в CSS-строку-константу, которую компонент рендерит как
`<style href="a2ui-constructions-editor" precedence="default">{CSS}</style>`.
React 19 (уже в `peerDependencies`) сам поднимает такой тег в `<head>` и
дедуплицирует по `href` — сколько бы редакторов ни было в треде, стиль один.

Почему не альтернативы:

- **Отдельный `styles.css` + импорт** — требует бандлера в сборке пакета,
  снимает `sideEffects: false` и заставляет каждого потребителя добавить
  импорт. Спека прямо требует «без отдельного импорта хостом».
- **Ручная инжекция в `document.head` через `useEffect`** — то же самое, но
  своими руками, плюс ломается в SSR (у потребителей `spai-ui` — Next.js).
- **CSS-in-JS библиотека** — новая зависимость ради одного компонента.
- **Оставить инлайн, адаптив на `ResizeObserver`** — JS-раскладка вместо CSS:
  лишний ререндер на каждый ресайз и мигание при первой отрисовке.

Классы префиксуются `a2ui-ce-` — глобальный CSS в чужом хосте, изоляции нет,
префикс единственная защита от коллизий. Цвета остаются `var(--a2ui-*)`:
тематизация не меняется.

### Решение 2: Брейкпоинт — container query, одно пороговое значение

Корень компонента получает `container-type: inline-size` и имя контейнера;
раскладка — `@container (min-width: 560px)`. Одно пороговое значение на весь
компонент: две колонки выше, одна ниже. Больше порогов не заводим, пока макет
не потребует — каждый порог это отдельная комбинация для проверки.

`@media` не годится: компонент живёт в чат-колонке, ширина которой зависит от
сайдбара, а не от окна. Проверять окно — значит рисовать две колонки в
480-пиксельной колонке на широком мониторе.

`FIELD_COLUMN_WIDTH` из `shared.ts` **не удаляется** — на него завязан
`LiftEditor` (`lift-editor-screen.tsx:44`), который этот change не трогает.
Убираются только его применения в файлах `constructions-editor-*`.

### Решение 3: `gsop` — поле `general`, а не вычисление

ГСОП показывается рядом с городом, но считается агентом и приходит в
`general.gsop`. Клиент его не выводит из `tot`/`zot`: коэффициенты табл. 3
СП 50 на клиент не переезжают (то же решение, что в
`constructions-editor-general-tab` про Rнорм). Правка климата пользователем
делает показанный ГСОП устаревшим — это ровно тот же случай, что `climateDirty`
для чипов Rнорм, и решается тем же снимком: при `climateDirty` ГСОП скрывается
до следующего ответа агента.

### Решение 4: `general` остаётся плоским, источники — параллельным блоком

Источник значения кладётся не внутрь поля (`{value, source}`), а в отдельный
проп `generalSources: Partial<Record<keyof ConstructionsGeneral, FieldSource>>`.

Почему так: `general` уходит в submit-payload как есть, и агент читает
`general.tv` числом. Обернуть значения в объекты — сломать payload всем
существующим эмитентам ради данных, которые агенту не нужны (он сам их
прислал). Параллельный блок оставляет payload прежним, а `generalSources`
просто не попадает наружу.

Цена: связь «поле ↔ источник» по строковому ключу, схема должна её проверять —
`z.object` с теми же ключами, что у `general`, все опциональные, `.strict()`.

### Решение 5: Снятие provenance — по факту правки, не по сравнению значений

Компонент держит `Set` тронутых ключей `general`. Ключ попадает в набор при
любом изменении поля и покидает его только при новом снимке props (ответ
агента). Сравнение текущего значения с исходным не используется: пользователь,
вернувший +21 обратно после правки, всё равно проверил поле — возвращать ему
подпись «предложено агентом» неверно.

Набор сбрасывается там же, где сейчас сбрасывается `general` при смене
`baseClimate` (`constructions-editor.tsx:87-91`) — новый ответ агента несёт и
новые значения, и новые источники.

### Решение 6: Свёрнутое состояние — локальный state, начальное — из props

`conditionsCollapsed` читается один раз как начальное значение локального
state. Агент управляет первым показом (в макете «Бриф — здание из
8 конструкций» условия свёрнуты, в «Брифе без проекта» — раскрыты), дальше
состоянием владеет пользователь. Сводка строится компонентом из текущих
значений — присылать её текстом значит гарантировать расхождение с полями
после первой же правки.

### Решение 7: «Назначение помещений» — только подпись и место

Поле `buildingType` не меняет контракт: список при заданном
`buildingTypeOptions`, свободный ввод без него — как сейчас. Меняются только
подпись («Тип здания» → «Назначение помещений») и место (второе поле сетки
условий). Аналогично `condition`: значение по умолчанию — Б — уже действует
(`general.condition = null` → λБ), в макете это просто видно.

### Решение 8: `tot`/`zot`/`tn` не исчезают, а уезжают во второй ряд

В макете видны только четыре поля. Но климат остаётся частью payload'а и
единственным способом починить неверно подставленный город. Прятать
редактируемое значение так, что пользователь не может его найти, — хуже, чем
показать компактной строкой. Три поля идут отдельным рядом «Климат» внутри
раскрытого блока, ниже основной сетки.

Решено: поля добавляем. Это осознанное отступление от макета.

## Risks / Trade-offs

- **Глобальный CSS в чужом хосте** → префикс `a2ui-ce-` на всех классах;
  специфичность держим на одном уровне (один класс), чтобы хост мог
  переопределить своим правилом без `!important`.
- **`precedence` — React 19-only API** → в `peerDependencies` уже `^19.0.0`;
  на React 18 компонент и сейчас не заявлен как рабочий.
- **SSR: `<style>` в потоке** → React 19 hoisting работает и на сервере; но
  первый серверный рендер потребителя (`spai-ui`, Next.js) надо проверить
  руками — юнит-тесты этого не поймают.
- **Container queries** → поддержка есть во всех целевых браузерах с 2023 г.;
  фолбэка не делаем, при отсутствии поддержки раскладка деградирует в одну
  колонку (пишем узкую раскладку как базовую, широкую — внутри `@container`).
- **Потеря инлайн-стилей ломает существующие тесты раскладки** → тесты в
  `tests/react` проверяют поведение, а не `style`-атрибуты; проверить перед
  переездом и переписать те, что смотрят на инлайн-стиль.
- **Удаление табов — видимая ломка для `spai-teplo-calc`** → пропы табов
  остаются валидными, экран просто перестраивается; агент менять не обязан,
  но подписи вкладок у него становятся мёртвым кодом.

## Migration Plan

1. Схема и Pydantic-зеркало — аддитивно, старые фикстуры остаются валидными.
2. CSS-слой и переезд `constructions-editor-*` на классы — без изменения
   поведения, отдельным шагом, чтобы регресс раскладки был виден в диффе.
3. Блок условий вместо табов + `gsop`.
4. `generalSources` и подписи.
5. Фикстуры: новая валидная фикстура с `generalSources`, `gsop` и свёрнутым
   блоком; существующие не трогаем — они проверяют обратную совместимость.

Откат — версией пакета: изменений в данных и хранилищах нет.

## Open Questions

Снято: `readonly` и подпись «изменить только для расчёта» из макета в этот
change не входят — поле с `source: 'project'` получает приглушённый вид и
подпись «из проекта», без обещаний о том, куда уедет правка. Вернуть можно
аддитивно, когда агент подтвердит гарантию.
