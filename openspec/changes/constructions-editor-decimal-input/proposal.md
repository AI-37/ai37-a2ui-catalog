# Редактор конструкций: дробный ввод через запятую

## Why

Все числовые поля редактора конструкций рендерятся как `<input type="number">`:

- `constructions-editor-layer-row.tsx` — толщина слоя, ручная λ;
- `constructions-editor-passport.tsx` — Rпр по паспорту;
- `constructions-editor-general.tsx` — климат (tот, zот, tн, tв).

`type="number"` не понимает запятую: браузер считает `0,1` невалидным и отдаёт
в `event.target.value` пустую строку. Пользователь видит `0,1` в поле (скрин
формы слоя «λ, Вт/(м·°C)»), а в состояние редактора уезжает `null` — «Применить»
записывает слой без λ, и карточка загорается «! проверить». Молчаливая потеря
ввода, а не ошибка.

Вторая половина беды — контролируемое числовое состояние. Обработчики делают
`Number.parseFloat(raw)` на каждый keystroke и кладут в черновик **число**, а
инпут рендерится из этого числа. Промежуточный ввод (`0,`, `0.`, `-`) в число
не разбирается или разбирается с потерей хвоста, поэтому даже с точкой набор
дроби «дёргается»: разделитель стирается на лету.

Тот же корень — в редакторе лифтов (`lift-editor-field.tsx`, ветка
`field.type === 'number'`), проверено по коду: запятая режется браузером, а
`type=number` без `step` вдобавок валидирует только целые. Там значение живёт
строкой и нормализуется агентом (`coerceFormValues`, `liftValuesMatch` уже
терпят `,`), так что нужен только правильный рендер.

## What Changes

- Общий хелпер `parseDecimalInput(raw): number | null` в `catalog-react`
  (trim, `,`→`.`, `Number.parseFloat`, отсев не-finite) — одна точка разбора
  десятичного ввода вместо трёх копий `Number.parseFloat`.
- Числовые поля редактора конструкций: `type="text"` + `inputMode="decimal"`
  вместо `type="number"`. Атрибуты `min`/`step` уходят вместе с ним — валидация
  остаётся там, где была (`findInvalidLayers`, подсветка «проверить»).
- Формы держат **сырой текст** редактируемого числового поля, а не число:
  что набрано, то и показано; разбор в число — на коммите (и для live-Rпр —
  по последнему разобранному значению). Промежуточные `0,` / `0.` / `-`
  переживают перерисовку.
- Редактор лифтов: number-поле рендерится как `type="text"` +
  `inputMode="decimal"`; значение по-прежнему уезжает строкой, нормализует
  агент.

## Impact

- Затрагивает `@ai37/a2ui-catalog-react`: `constructions-editor-layer-row`,
  `constructions-editor-passport`, `constructions-editor-general`,
  `lift-editor-field` + новый `parse-decimal-input.ts`.
- Схемы (`catalog-schemas`) не меняются: `thicknessMm`, `lambdaManual`,
  `rprPassport`, климат — как были, числа; меняется только путь ввода.
- Теряется нативный spinner (↑↓) у числовых полей — приемлемо, дробный ввод
  дороже стрелок; тот же размен уже принят черновиком
  `form-card-number-text-decimal`.
- Форматирование вывода не меняется: канонические значения показываются с
  точкой (`0.048`, `value.toFixed(2)`).

## Open questions

- Не совпадёт ли этот change с `form-card-number-text-decimal` в одном месте
  кода? Нет: тот трогает `form-card.tsx`, здесь его нет. Общим у них станет
  `parseDecimalInput` — если FormCard-черновик поедет первым, хелпер заводит он.
- Показывать ли вывод с запятой (локализованный формат)? Non-goal: ввод
  терпимый, вывод остаётся машинно-единообразным.
