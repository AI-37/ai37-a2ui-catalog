# Design: VerificationReport

## Решения

1. **Отдельный компонент без суффикса `Next`.** Суффикс в семействе значит
   «второй рендерер того же контракта»; у проверки контрагента legacy-близнеца
   нет. Собран на тех же примитивах, что `*ReportNext`. *Решение плана (#470).*
2. **Раскрывается только строка, у которой есть `details` или `sources`.**
   Флага «раскрываемая» в контракте нет: строка без деталей — не кнопка, иначе шеврон обещает пустую панель. *Решение плана.*
3. **Несколько строк открыты одновременно** (`Accordion multiple`).
   Проверяющий сравнивает основания соседних проверок — ОКВЭД рядом с
   финансами; в редакторах одна-за-раз нужна для навигации «Далее», здесь
   навигации нет. *Решение исполнителя, по сценарию из отзыва.*
4. **Основание видно без раскрытия.** `summary` строки стоит второй строкой
   заголовка для всех статусов, включая «пройдена» — это и был пробел
   markdown-вывода.
5. **Слова статуса — в рендерере**, как `REPORT_NEXT_STATUS_TEXT`:
   Пройдена / Не пройдена / Внимание / Ошибка / Пропущена. `error` красится
   провалом (проверка не состоялась — смотреть), `skipped` — нейтрально.
   Слово вердикта (`badge`) пишет агент: у вердиктов агента свои
   формулировки (`decision_display_ru`).
6. **URL источника схема не валидирует форматом**, ссылкой рендерер делает
   только `http(s)`; остальное — подписью. `z.string().url()` дал бы
   `format: uri` в JSON Schema без пары в Pydantic-зеркале и всё равно
   пропустил бы `javascript:`. Ссылки открываются в новой вкладке с
   `rel="noopener noreferrer"`.
7. **Без действий.** Отчёт ничего не диспатчит, поэтому на прошлой
   поверхности не глушится (`withReadOnlyGate` не нужен) — раскрытие
   работает, как у остальных отчётов (канон 0.39.2).

8. **Строка собрана из частей `SectionItem`, а не им самим.** `SectionItem`
   ставит заголовок и сводку в одну строку, а заголовок держит без переноса.
   На проверке это ломается: на ширине 360 px «Реестр недобросовестных
   поставщиков (РНП)» вылезал за карточку, а основание сжималось в столбик
   в 3–4 слова (снимок до правки — в истории ветки). Поэтому строка взята
   из тех же частей (`Accordion.Item` с `cardClassName`, `CardHeader`,
   `buttonClassName` с `a2ui-card__title`, `ChevronIcon`), но название и
   основание стоят друг под другом. Плоская строка (без деталей) выложена так
   же, с пустым местом на месте шеврона, поэтому названия всех строк стоят в
   одну линию. Плоская строка `ReportRow` тоже отпала: рядом с раскрываемыми
   строками она выглядела бы по-другому. *Решение исполнителя по скриншотам
   гейта.*

## Темы

Светлая и тёмная — от набора: своих цветов у рендерера нет, всё через
токены примитивов.

## Открытые вопросы

- Подписи значений и состав `details` по каждой проверке выбирает агент
  (`minstroy/app/spai/verification_report.py`); если проверяющий попросит
  другие поля — правка в агенте, не в каталоге.
