## ADDED Requirements

### Requirement: Pending-навигация раскрывает только целевую карточку

При заданном `pendingLabel` и заполненных обязательных полях условий клик по
pending-кнопке SHALL раскрывать первую сверху карточку, требующую внимания, и
одновременно сворачивать все остальные карточки: после клика раскрытой SHALL
остаться ровно одна — целевая. Статус целевой карточки SHALL гаситься по
общему правилу просмотра (раскрытие без ошибок данных). Action при этом
SHALL NOT отправляться.

#### Scenario: Первый шаг навигации

- **WHEN** условия заполнены, две карточки со статусом `confirm`, все свёрнуты,
  и пользователь нажимает pending-кнопку
- **THEN** раскрыта только первая карточка
- **AND** её статус погашен («готова»)

#### Scenario: Следующий шаг сворачивает предыдущую

- **WHEN** после первого шага пользователь снова нажимает pending-кнопку
- **THEN** раскрыта только вторая карточка
- **AND** первая свёрнута и остаётся «готова»

#### Scenario: Раскрытая вручную карточка сворачивается при навигации

- **WHEN** пользователь вручную раскрыл карточку без пометок, а затем нажал
  pending-кнопку, ведущую к другой карточке
- **THEN** раскрыта только целевая карточка

### Requirement: Ручное раскрытие карточек остаётся мульти-open

Ручной клик по заголовку карточки SHALL переключать только её собственное
состояние: другие раскрытые карточки SHALL NOT сворачиваться.

#### Scenario: Две карточки раскрыты руками

- **WHEN** пользователь кликами по заголовкам раскрывает две карточки подряд
- **THEN** обе раскрыты

### Requirement: Навигация к условиям не трогает карточки

Если обязательные поля условий не заполнены, клик по pending-кнопке SHALL
раскрывать блок условий, не меняя состояния карточек.

#### Scenario: Незаполненные условия при раскрытой карточке

- **WHEN** условия не заполнены, одна карточка раскрыта вручную, и
  пользователь нажимает pending-кнопку
- **THEN** блок условий раскрыт
- **AND** раскрытая карточка осталась раскрытой
