## Requirements
### Requirement: Строковая подпись поля рендерит индекс подстрочным

Строковый `label` поля схемного редактора ДОЛЖЕН (SHALL) рендериться так, что
конструкция «буква + `_` + индекс из 1–3 букв или цифр» на границах токена
показывается как база с подстрочным индексом (`d_п` → d`<sub>`п`</sub>`), без
видимого подчёркивания.

Текст вне таких конструкций изменяться НЕ ДОЛЖЕН (SHALL NOT); длинные
конструкции с `_` (базы больше одной буквы, индексы длиннее трёх знаков)
трактоваться индексом НЕ ДОЛЖНЫ (SHALL NOT).

JSX-подпись (не строка) обрабатываться НЕ ДОЛЖНА (SHALL NOT) — она уже
свёрстана рендерером.

#### Scenario: Подпись с индексом

- **WHEN** поле приходит с `label: 'd_п — глубина помещения, м'`
- **THEN** на экране «d» с подстрочным «п», далее « — глубина помещения, м»
- **AND** символ `_` не виден

#### Scenario: Подпись без индексов

- **WHEN** поле приходит с `label: 'Остекление'`
- **THEN** подпись показана без изменений

#### Scenario: Подчёркивание в обычном слове

- **WHEN** в подписи встречается `some_word`
- **THEN** оно показано как есть, без подстрочных индексов

### Requirement: Сводка свёрнутой секции рендерит те же индексы

Строка-сводка свёрнутой секции ДОЛЖНА (SHALL) рендериться по тому же правилу
подстрочных индексов — заголовок свёртки собирается из `shortLabel` и значений.

#### Scenario: Заголовок свёртки

- **WHEN** секция «Геометрия помещения» свёрнута со значениями
- **THEN** сводка показывает «d<sub>п</sub> 5.4 · b<sub>п</sub> 3.4 · …»
  подстрочными индексами

### Requirement: Правило одно на каталог

Распознавание и рендер индексов ДОЛЖНЫ (SHALL) жить в одном хелпере и
применяться на уровне примитивов (`Field`, `SummaryCollapsible`) — так, что
любой схемный редактор получает поведение без правок своего рендерера.

#### Scenario: Другой схемный редактор

- **WHEN** `LiftEditorNext` показывает поле или сводку со строкой вида `t_и`
- **THEN** индекс рендерится подстрочным без изменений в его рендерере

### Requirement: Чипы исходных данных отчёта рендерят индексы подстрочными

Подписи чипов, заголовки и note групп «Исходных данных» ДОЛЖНЫ (SHALL)
рендериться по правилу подстрочных индексов `label-subscripts`:
`d_п · b_п · h, м` показывается базами с подстрочными индексами, без `_`
на экране.

Значения чипов (`chip.value`) обрабатываться НЕ ДОЛЖНЫ (SHALL NOT).

#### Scenario: Чип с индексами

- **WHEN** отчёт приходит с чипом `label: 'd_п · b_п · h, м'`
- **THEN** подпись показана как «d<sub>п</sub> · b<sub>п</sub> · h, м»

#### Scenario: Note группы коэффициентов

- **WHEN** группа приходит с note, называющей `ε_б` и `ε_зд`
- **THEN** индексы «б» и «зд» показаны подстрочными

#### Scenario: Чип без индексов

- **WHEN** отчёт приходит с чипом `label: 'Ориентация'`
- **THEN** подпись показана без изменений
