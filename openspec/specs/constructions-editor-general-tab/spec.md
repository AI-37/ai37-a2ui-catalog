## Requirements
### Requirement: Табы «Общие данные» и «Конструкции»

`ConstructionsEditor` SHALL показывать две вкладки — общие данные и
конструкции — и переключать их локально, без `dispatchAction`. Активная
вкладка SHALL быть частью локального состояния компонента; при переключении
введённое на обеих вкладках SHALL сохраняться.

#### Scenario: Переключение не ходит к агенту

- **WHEN** пользователь переключает вкладку
- **THEN** ни один action не отправляется

#### Scenario: Данные переживают переключение

- **WHEN** пользователь ввёл название конструкции, ушёл на «Общие данные»,
  ввёл tв и вернулся на «Конструкции»
- **THEN** название конструкции на месте
- **AND** введённое tв на месте

#### Scenario: Кнопка возврата не обязательна

- **WHEN** агент прислал props без `backLabel` и `backAction`
- **THEN** props проходят валидацию схемы
- **AND** компонент не показывает кнопку возврата

#### Scenario: Кнопка возврата задана

- **WHEN** агент прислал `backLabel` и `backAction`
- **THEN** компонент показывает кнопку, и нажатие шлёт `backAction` без
  валидации, как прежде

### Requirement: Кнопка «Далее» на вкладке общих данных

На вкладке общих данных вместо submit'а SHALL показываться кнопка перехода к
конструкциям (подпись — `nextLabel`, по умолчанию «Далее»), переключающая
вкладку локально, без `dispatchAction`. Сводка «проходит N из M» на этой
вкладке SHALL NOT показываться: она относится к конструкциям. Submit
SHALL быть доступен на вкладке конструкций.

#### Scenario: Переход к конструкциям

- **WHEN** пользователь ввёл tв и нажал «Далее»
- **THEN** открыта вкладка конструкций, ни один action не отправлен
- **AND** при возврате на общие данные введённое tв на месте

#### Scenario: Вкладка общих данных без submit'а

- **WHEN** активна вкладка общих данных
- **THEN** кнопки submit'а и сводки «проходит N из M» на экране нет

### Requirement: Props блока общих данных

Схема SHALL принимать блок `general` с полями `buildingType`, `city`, `tot`,
`zot`, `tn`, `tv`, `condition`, где незаполненное значение — `null`, а
`city` — пара `{value, label}` либо `null`. Схема SHALL принимать
`buildingTypeOptions` (список вариантов типа здания) и `cityReferenceId`
(справочник городов для lookup'а). Все поля вкладки SHALL быть редактируемыми.

#### Scenario: Пустой блок

- **WHEN** агент прислал `general` со всеми значениями `null`
- **THEN** props проходят валидацию схемы
- **AND** вкладка общих данных показывает пустые поля

#### Scenario: Тип здания по умолчанию

- **WHEN** `general.buildingType` пуст, а `buildingTypeOptions` не пуст
- **THEN** выбран первый вариант списка
- **AND** пустой выбор остаётся доступным

#### Scenario: Неизвестный ключ

- **WHEN** в `general` есть ключ вне схемы
- **THEN** валидация отклоняет props

#### Scenario: Правка значения

- **WHEN** пользователь меняет tв
- **THEN** новое значение попадает в локальное состояние и уходит в
  ближайший submit

### Requirement: Lookup города заполняет климат

Поле города SHALL работать через тот же fetch-канал подсказок, что и материалы
(`cityReferenceId`, `minChars`). Если выбранная опция несёт поля `tot`, `zot`,
`tn`, компонент SHALL подставить их значения в соответствующие поля вкладки.
Подставленные значения SHALL оставаться редактируемыми.

#### Scenario: Опция с климатом

- **WHEN** пользователь выбирает город, опция которого несёт
  `tot: -6.4, zot: 218, tn: -33`
- **THEN** поля tот, zот, tн получают эти значения
- **AND** поле города показывает label опции

#### Scenario: Опция без климата

- **WHEN** выбранная опция не несёт климатических полей
- **THEN** заполняется только город, остальные поля не меняются

#### Scenario: Ручная правка после подстановки

- **WHEN** после выбора города пользователь меняет zот вручную
- **THEN** введённое значение сохраняется и уходит в submit

#### Scenario: Смена города

- **WHEN** пользователь выбирает другой город, опция которого несёт климат
- **THEN** поля климата перезаписываются значениями новой опции

### Requirement: Submit без клиентской блокировки

`submitAction` SHALL отправляться при каждом нажатии кнопки submit, независимо
от заполненности полей, с контекстом `{general, constructions}` — полным
текущим состоянием обеих вкладок, включая пустые и невалидные записи.
Компонент SHALL NOT блокировать submit и SHALL NOT подсвечивать обязательные
поля: о недостающем сообщает агент.

#### Scenario: Пустая форма

- **WHEN** пользователь нажимает submit при незаполненных общих данных и
  пустом списке конструкций
- **THEN** уходит один action `submitAction`
- **AND** `context.general` содержит `null`-значения, `context.constructions`
  — пустой массив

#### Scenario: Частично заполненная форма

- **WHEN** заполнены общие данные и одна конструкция без толщины слоя
- **THEN** уходит один action с этим состоянием как есть
- **AND** поле толщины не подсвечивается ошибкой

### Requirement: Чипы Rнорм скрываются без честных данных

Сравнение `Rпр` с `Rнорм` и сводка «проходит N из M» SHALL показываться только
когда `typeConfigs[].rnorm` задан **и** поля климата не менялись с момента
получения props. При изменении любого поля климата — `tot`, `zot`, `tn`, `tv`,
`buildingType`, `city` — компонент SHALL скрыть сравнение и сводку, оставив
значение `Rпр` без сравнения, до следующих props от агента.

#### Scenario: Климат не тронут

- **WHEN** props содержат `rnorm` и пользователь правит только слои
- **THEN** чип показывает сравнение вида «Rпр 3,61 ≥ 2,93»
- **AND** сводка «проходит N из M» видна

#### Scenario: Климат тронут

- **WHEN** пользователь меняет zот
- **THEN** чипы показывают только «Rпр 3,61», без сравнения
- **AND** сводка «проходит N из M» не отображается

#### Scenario: Rнорм не прислан

- **WHEN** у типа конструкции нет `rnorm`
- **THEN** сравнение для этой конструкции не показывается независимо от
  климата

#### Scenario: Новые props восстанавливают чипы

- **WHEN** агент прислал форму заново с пересчитанным `rnorm`
- **THEN** сравнение и сводка показываются снова

### Requirement: Условие эксплуатации живёт во вкладке

Выбор λА/λБ в live-расчёте `Rпр` SHALL брать значение `condition` из текущего
состояния вкладки общих данных. Top-level проп `condition` SHALL
использоваться только как начальное значение и считается устаревшим. Отсутствие
значения SHALL означать λБ — как на сервере.

#### Scenario: Переключение условия пересчитывает Rпр

- **WHEN** пользователь меняет условие с Б на А
- **THEN** live-значения `Rпр` пересчитываются по λА

#### Scenario: Условие не задано

- **WHEN** `condition` отсутствует и в `general`, и в top-level пропе
- **THEN** live-расчёт использует λБ

### Requirement: Черновик покрывает обе вкладки

При заданном `draftAction` контекст черновика SHALL содержать
`{general, constructions}`. Триггеры отправки остаются прежними — структурные
правки списка конструкций.

#### Scenario: Черновик после правки общих данных

- **WHEN** пользователь ввёл город на вкладке общих данных, затем добавил
  конструкцию
- **THEN** уходит один `draftAction`
- **AND** его `context.general` содержит введённый город
